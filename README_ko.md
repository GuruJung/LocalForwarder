# LocalForwarder

[English](README.md) · 한국어

LocalForwarder는 macOS와 Windows에서 SSH 로컬 포워딩을 관리하는 작은 네이티브 앱입니다. 메뉴 막대 또는 시스템 트레이 아이콘 하나로 여러 호스트의 연결을 관리합니다. 운영체제의 OpenSSH가 인증과 데이터 전송을 담당하고, LocalForwarder는 설정과 연결 조작을 제공합니다.

## 다운로드와 실행

| 시스템 | CPU | 다운로드 |
|---|---|---|
| macOS 15 이상 | Apple Silicon ARM64 | `LocalForwarder-<version>-macos-arm64.zip` |
| Windows 11 | x64 | `LocalForwarder-<version>-windows-x64.zip` |
| Windows 11 | ARM64 | `LocalForwarder-<version>-windows-arm64.zip` |

[GitHub Releases](https://github.com/GuruJung/LocalForwarder/releases)에서 공개된 버전을 다운로드하세요. 위 파일명의 `<version>`은 릴리스 버전(시작값 `0.1.0`)입니다. ZIP을 풀고 `.app` 또는 `.exe`를 실행합니다.

개발 빌드는 [GitHub Actions](https://github.com/GuruJung/LocalForwarder/actions/workflows/build.yml)의 성공한 실행을 열고 **Artifacts**에서 해당 플랫폼의 패키지를 다운로드하세요. 다운로드에는 GitHub 로그인이 필요하며 결과물은 7일간 보관됩니다. Artifact 압축 파일과 그 안의 배포 ZIP을 모두 푼 뒤 macOS에서는 `.app`, Windows에서는 `.exe`를 실행합니다. 별도 설치 프로그램은 필요하지 않습니다.

macOS 앱은 ad-hoc 서명하며 공증하지 않고, Windows 실행 파일에는 서명 인증서가 없습니다. macOS가 실행을 차단하면 출처를 확인한 뒤 **시스템 설정 → 개인정보 보호 및 보안**에서 허용하세요. Windows에서는 SmartScreen 경고가 나타날 수 있습니다. 조직에서 실행을 제한한다면 해당 정책을 따르세요.

macOS는 `/usr/bin/ssh`를 사용합니다. Windows에는 시스템 **OpenSSH Client 9.5 이상**이 필요하며 PowerShell에서 확인할 수 있습니다.

```powershell
& "$env:WINDIR\System32\OpenSSH\ssh.exe" -V
```

구버전 Windows 클라이언트는 Windows Update 또는 [Microsoft의 OpenSSH 업데이트 안내](https://learn.microsoft.com/en-us/troubleshoot/windows-server/system-management-components/upgrade-in-box-openssh-to-latest-openssh-release)에 따라 업데이트하세요. 앱은 SSH 설치, 관리자 권한 요청, 서비스 설정 변경을 하지 않으며 Git for Windows의 SSH를 사용하지 않습니다. 원격 서버에는 이 Windows 클라이언트 버전 조건을 요구하지 않습니다.

## 빠른 시작

앱은 메뉴 막대 또는 시스템 트레이에 계속 표시됩니다. 처음 실행하거나 `--open-config`로 실행하면 설정창을 엽니다. 다시 실행하면 기존 앱의 설정창이 열립니다.

1. 새 호스트를 만들고 이름과 SSH 별칭 또는 주소를 입력합니다. `~/.ssh/config`의 별칭도 사용할 수 있습니다. 선택 사항인 한 줄 설명으로 호스트의 용도를 적을 수 있습니다.
2. 필요한 경우 사용자명, SSH 포트, 개인키 경로를 지정합니다. 빈 접속 항목은 SSH 설정을 따릅니다.
3. **새 규칙…**에서 로컬 포트, 목적지 호스트와 포트를 입력하고 필요하면 설명을 추가합니다. **규칙 편집…**이나 더블클릭으로 수정하고 체크박스로 규칙을 비활성화합니다. 규칙 확인은 초안만 바꾸며 파일을 저장하지 않습니다.
4. 선택 호스트를 **저장**합니다. 자동 연결, `ExitOnForwardFailure`, 연결 거부 시 재시도는 기본 ON입니다.
5. 호스트를 연결합니다. 미저장 편집이 있는 상태에서 재연결하면 저장 후 재연결 / 저장 없이 재연결 / 취소를 선택할 수 있습니다. 설정창의 **확인**은 자동 저장하지 않습니다.

예를 들어 `15432 → 127.0.0.1:5432`는 내 컴퓨터의 `127.0.0.1:15432`를 **SSH 서버에서 보는** `127.0.0.1:5432`로 연결합니다. 데이터베이스 클라이언트에는 로컬 주소를 지정하세요. 앱 규칙은 IPv4 루프백(`127.0.0.1`)에만 바인딩합니다. 기존 SSH의 `LocalForward`, `RemoteForward`, `DynamicForward`도 원래 바인딩 주소대로 함께 실행합니다.

시작 설정창에서 **확인**을 누르면 저장된 자동 연결 ON 호스트들을 연결하고, **취소**를 누르면 연결 없이 트레이 모드로 들어갑니다. 기존 정상 설정으로 일반 실행하면 자동 연결 ON 호스트들을 연결합니다. 설정창 닫기나 개별 연결 실패로 앱이 종료되지는 않습니다. 모든 연결을 끊고 앱을 닫으려면 트레이의 **종료**를 사용하세요.

포워딩 목록 아래의 **로컬 포트순 정렬**을 누르면 선택한 호스트의 규칙을 로컬 포트 번호가 작은 순서로 정렬합니다. 비활성 규칙도 포함하며 같은 포트끼리는 기존 순서를 유지합니다. 정렬은 초안만 변경하고 SSH를 다시 연결하지 않습니다. 설정창을 다시 열거나 앱을 재시작한 뒤에도 순서를 유지하려면 선택 호스트를 저장하세요. 정렬은 버튼을 누를 때만 적용되며 규칙 추가·편집 후 자동으로 정렬하지 않습니다.

## 표시 언어

트레이 메뉴에서 **설정** 바로 아래의 **언어**를 선택합니다. 영어·한국어·중국어 간체·중국어 번체·일본어·스페인어·독일어를 내장 지원합니다. 최초 실행은 **자동(시스템 언어)**이며 OS의 선호 UI 언어 중 처음 지원되는 언어를 사용하고, 없으면 영어를 사용합니다. 간체는 중국 본토 용어, 번체는 대만 용어 기준입니다.

서브메뉴는 자동, 구분선, 영어 이름 알파벳순의 언어 목록이며 자국어 이름을 함께 표시합니다. 선택한 항목 하나에만 체크하고, 자동 항목에는 실제 적용 언어도 표시합니다. 선택은 호스트 설정과 별도로 현재 OS 사용자에게 저장됩니다.

언어는 즉시 변경되며 SSH 연결과 미저장 입력을 보존합니다. 모달 대화상자는 닫은 뒤 언어를 변경하세요. 실행 중인 인증 터미널은 시작 당시 언어를 유지합니다. 사용자 이름·설명, SSH 출력, OS 제공 대화상자는 원래 언어를 따릅니다. 자동 선택은 시작 시와 자동 항목을 선택할 때 평가하므로 OS 언어 변경 후에는 앱을 다시 실행하거나 자동을 다시 선택하세요. 외부 언어 파일은 읽지 않습니다.

## 연결과 트레이

트레이 메뉴에는 설정, 언어, 로그인 자동 시작, 전체 재연결, 전체 연결 끊기, 호스트별 메뉴, About..., 종료가 있습니다. 호스트 메뉴에는 SSH 요약, 규칙별 정보와 상태 아이콘, 연결 동작이 표시됩니다. 비활성 규칙도 표시됩니다. 자세한 오류와 저장 설정·실행 중 연결의 차이는 설정창의 **연결 상태…**에서 확인하세요.

저장은 선택한 호스트만 변경하며 현재 연결과 다른 호스트의 미저장 초안은 유지합니다. 변경은 다음 연결부터 적용됩니다. 저장 없이 연결하면 임시 설정이 수동 재연결과 자동 복구에도 사용되며, 이후 편집을 취소해도 실행 중인 설정은 되돌리지 않습니다. 해당 호스트를 명시적으로 저장하면 다음 연결부터 임시 설정 대신 저장값을 사용합니다. 저장 없이 연결한 신규 호스트는 앱 종료 전까지만 유지됩니다.

**전체 재연결**은 임시 설정을 해제하고 저장된 자동 연결 ON 호스트만 다시 연결합니다. 자동 연결 OFF인 호스트도 수동 연결할 수 있습니다. 수동으로 끊으면 현재 실행 중에는 자동 복구하지 않지만 저장된 자동 연결 옵션은 바뀌지 않습니다.

**전체 연결 끊기**는 한 번 확인한 뒤 수동 연결과 미저장 임시 호스트를 포함한 모든 호스트를 끊고 연결 시도·재시도·자동 복구 대기도 취소합니다. 기본 선택은 취소입니다. 앱은 트레이에 남으며 저장된 자동 연결 옵션, 미저장 편집, 임시 실행 설정은 보존됩니다. 다시 연결하거나 정상 시작 정책에 따라 앱을 재시작하기 전까지 자동 복구하지 않습니다. 끊을 연결이나 작업·연결 의도가 없으면 메뉴가 비활성화됩니다.

**About...**은 앱 아이콘·이름·제품 버전·MIT License·GitHub 링크를 표시하는 모달을 엽니다. 버전 아래의 MIT License 링크는 저장소의 LICENSE 전문을 엽니다. 기존 연결은 유지하며, 두 링크는 클릭할 때만 기본 브라우저를 엽니다. 닫기 버튼이나 Escape로 닫습니다.

절전 복귀 또는 네트워크 사용 불가→사용 가능 전환 후 **마지막 이벤트부터 5초 뒤** 복구합니다. 연결을 유지하도록 요청된 호스트 중 실제로 끊긴 호스트만 대상입니다. 정상 연결, 연결 시도 중, 수동 단절 호스트는 건드리지 않습니다. 다시 오프라인이 되면 대기 중 복구를 취소합니다. 설정창 열기나 앱 포커스 복귀는 복구 계기가 아닙니다. 복구 이후 늦게 감지한 단절은 다음 이벤트나 수동 연결을 기다립니다.

연결 거부 시 재시도 옵션이 ON이면 연결 성립 전 명시적인 접속 거부·조기 종료·리셋에 한해 **1초 뒤 한 번** 재시도합니다. 인증 오류, 호스트 키 오류, 포트 충돌, 일반 타임아웃에는 재시도하지 않습니다.

포워딩 상태는 준비 중, 준비됨, 개설 실패, 연결 끊김, 확인 불가입니다. **준비됨은 포워딩 개설 성공이며 목적지 데이터베이스나 웹 서비스의 정상 동작을 보장하지 않습니다.** 목적지 서비스를 주기적으로 검사하지 않으며 관측된 실패는 최근 오류에 남깁니다. `ExitOnForwardFailure`를 끄면 일부 또는 전체 규칙이 실패해도 SSH 연결은 유지될 수 있습니다.

## 로그인 자동 시작

트레이의 **로그인 자동 시작**을 체크하면 현재 사용자의 로그인 때 앱을 실행하도록 등록하고, 체크를 해제하면 등록을 제거합니다. 기본값은 OFF이며 호스트별 자동 연결 옵션과 별개입니다. 변경해도 현재 연결은 유지되고 앱을 종료해도 등록은 유지됩니다.

- **macOS:** `등록 필요`는 OS 등록이 필요하다는 뜻입니다. `승인 필요`는 등록은 체크됐지만 시스템 승인이 필요한 상태이며, 선택하면 로그인 항목 설정을 엽니다. 체크를 해제하면 승인 대기 등록도 제거됩니다.
- **Windows:** 체크는 앱의 자동 시작 등록 여부입니다. 작업 관리자, Windows 설정이나 시스템 정책에서 별도로 차단했다면 해당 설정을 확인하세요. 앱이 이를 강제로 바꾸지는 않습니다.

앱을 계속 사용할 폴더에 둔 뒤 켜세요. 이동·삭제하면 자동 시작이 깨질 수 있습니다. 이동 후 새 위치에서 체크를 해제하고 다시 체크하세요. 정상 설정이 있으면 로그인 때 트레이로 시작하고 자동 연결 ON 호스트들을 연결합니다. 설정이 없거나 손상됐다면 일반 실행과 같은 설정 또는 오류 처리를 따릅니다. 로그인 실행 시점은 OS가 결정합니다.

## 설정 파일

양쪽 플랫폼 모두 실제 사용자 홈의 `.LocalForwarder/config.json`을 사용합니다. **설정 버전 2만 지원합니다.** 예시는 다음과 같습니다.

```json
{
  "version": 2,
  "hosts": [{
    "id": "development",
    "name": "개발 서버",
    "description": "개발 데이터베이스 접속",
    "target": "dev-server",
    "autoConnect": true,
    "exitOnForwardFailure": true,
    "retryOnConnectionRefused": true,
    "forwards": [{
      "id": "database",
      "enabled": true,
      "localPort": 15432,
      "remoteHost": "127.0.0.1",
      "remotePort": 5432,
      "description": "PostgreSQL"
    }]
  }]
}
```

호스트의 선택 필드는 `user`, `port`, `identityFile`, `description`입니다. 규칙에도 `description`을 지정할 수 있습니다. 설명은 개행과 NUL이 없는 한 줄 텍스트이며 누락·`null`·빈 문자열은 설명 없음으로 처리하고 빈 값은 저장 시 생략합니다. 규칙 설명은 설정창과 규칙 편집창에 표시합니다. 설명은 SSH 인수로 사용하지 않으며 연결 동작을 바꾸지 않습니다. 설명을 지원하지 않는 구버전 v2 앱에서 다시 저장하면 설명이 유실될 수 있습니다.

호스트 ID는 서로 고유해야 하고 규칙 ID는 해당 호스트 안에서 고유해야 합니다. 영문·숫자·하이픈·밑줄을 사용하세요. `autoConnect`, `exitOnForwardFailure`, `retryOnConnectionRefused`가 생략되면 기본 ON입니다. 비밀번호와 개인키 내용은 JSON에 저장하지 않습니다.

설정창을 열 때 파일을 다시 읽고 호스트를 바꿀 때는 초안을 유지합니다. 저장은 잠금 안에서 최신 파일의 선택 호스트만 원자적으로 갱신합니다. 같은 항목을 수정하면 마지막 저장을 따릅니다. 손상되거나 지원하지 않는 파일은 보존하고 자동 연결에 사용하지 않습니다.

v1 파일은 자동 변환하거나 새 이전 백업을 만들지 않고 거부합니다. 새로 시작하려면 앱과 인증 도우미를 종료하고 기존 `config.json`을 안전한 백업 위치로 옮긴 뒤 앱을 다시 열어 설정을 작성하세요. 이미 존재하는 백업은 변경하지 않습니다.

## 인증과 문제 해결

일반 연결에서는 입력을 요청하지 않습니다. 설정창에서 선택 호스트의 인증 설정을 실행하면 외부 터미널 도우미가 열리며 앱과 다른 연결은 유지됩니다. 인증 준비를 마친 뒤 직접 호스트를 연결하세요.

도우미는 기존 키를 우선 사용합니다. 새 키가 필요하면 `.LocalForwarder/keys/`에 암호 없는 Ed25519 키를 만듭니다. 일반 Linux/macOS 계정의 `~/.ssh/authorized_keys`에 기존 키와 제한 옵션을 보존하며 중복 없이 공개키를 등록합니다. 비밀번호와 기존 키 암호는 터미널에서만 입력합니다. 서버 인증 정책과 변경된 호스트 키 검증을 우회하지 않습니다. 원격 Windows 계정 자동 키 등록은 지원하지 않으며, 인증이 준비된 Windows SSH 서버에는 연결할 수 있습니다.

- **인증 실패:** 선택 호스트의 SSH 별칭, 사용자명, 키와 호스트 키 메시지를 확인하세요. Windows에서 암호화된 키를 쓰려면 `ssh-agent`가 준비돼 있어야 하며, 준비되지 않았으면 터미널 도우미가 설정 방법을 안내합니다. 앱은 키 암호를 제거하거나 임의로 키를 교체하지 않습니다.
- **SSH는 연결됐지만 서비스에 접근 불가:** 연결 상태를 확인한 뒤 서버 쪽에서 목적지 주소와 서비스를 확인하세요. `ExitOnForwardFailure`가 OFF라면 SSH 연결 중에도 실패한 규칙이 있는지 확인해야 합니다.
- **포트 충돌:** 호스트마다 서로 다른 로컬 포트를 쓰세요. 한 호스트 안의 활성 규칙 중복은 거부합니다. 호스트 간 충돌은 SSH 결과를 따르며 Windows OpenSSH가 포트 재사용을 허용할 수 있어, 중복 포트의 트래픽이 어느 목적지로 가는지 보장되지 않습니다.
- **어댑터 변경 후 복구 안 됨:** Windows는 전체 내부망 또는 인터넷 사용 가능 상태를 기준으로 합니다. 네트워크가 계속 사용 가능한 상태에서 어댑터만 바뀌면 복구 이벤트가 아닙니다. 필요하면 수동 재연결하세요.

## 빌드와 테스트

소스 저장소를 복제하거나 다운로드한 뒤 루트에서 명령을 실행하세요. macOS는 Xcode, Python 3.11 이상, 통합 테스트용 `sshd`를 포함한 시스템 OpenSSH 도구가 필요합니다.

```sh
bash scripts/eval-macos.sh
```

Windows는 PowerShell 7, 대상 아키텍처의 C++ 데스크톱 도구를 포함한 Visual Studio 또는 Build Tools, CMake 3.24 이상, Ninja, Python 3.11 이상, OpenSSH Client 9.5 이상, 통합 테스트용 OpenSSH Server 도구가 필요합니다.

```powershell
pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture x64
# ARM64 Windows:
pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture arm64
```

이 명령은 해당 플랫폼의 앱을 빌드·테스트·패키징합니다. ZIP은 다운로드 표의 파일명으로 `dist/`에 생성되며, macOS 앱은 `dist/LocalForwarder.app`, Windows 빌드는 `build/windows-<architecture>/`에 남습니다. 테스트 보고서는 `dist/`에 생성됩니다.

통합 테스트는 임시 키·설정과 루프백 SSH 서버를 사용하며 몇 분이 걸립니다. macOS의 일반 사용자 계정에서는 격리된 테스트 서버 실행에 `sudo -n` 권한이 필요하며 테스트 중 비밀번호 입력은 받을 수 없습니다. Windows에서는 시스템 OpenSSH 설치 또는 `LOCALFORWARDER_TEST_SSHD`로 `sshd.exe`를 제공하세요. Windows CI 서버 준비 스크립트는 일회성 GitHub 러너 전용이며 로컬 PC 설정 명령이 아닙니다. macOS의 실제 로그인 항목 등록 테스트도 일회성 GitHub 호스팅 CI에서만 실행합니다. 자동 테스트가 실제 절전·네트워크 전환과 데스크톱 동작 확인을 대신하지는 않습니다.

제품 의도와 개발 이슈는 [현재 명세](https://github.com/GuruJung/LocalForwarder/blob/main/docs/dev-plans/current-spec.md)에서 확인하세요.

## 버전 관리와 배포

`VERSION`은 macOS·Windows의 공통 제품 버전이며 설정 형식 `"version": 2`와는 별개입니다. 제품 버전을 바꾸려면 `VERSION`을 `major.minor.patch` 형식으로 수정한 뒤 추적 중인 Swift 버전 상수를 다시 생성하고 검사합니다.

```sh
python3 scripts/version.py --write
python3 scripts/version.py --check
python3 -m unittest discover -s tests -p 'test_release*.py'
```

`VERSION`과 생성된 Swift 파일을 함께 커밋합니다. Windows는 CMake가 `VERSION`을 읽습니다. 네이티브 평가 스크립트는 버전과 패키지 메타데이터를 검사합니다. About·OS 버전 정보·ZIP 파일명은 모두 같은 제품 버전을 사용합니다.

릴리스를 검토하고 커밋한 뒤 일치하는 태그(예: `v0.1.0`)를 명시적으로 생성·push합니다. 태그는 `v`와 `VERSION`을 붙인 값과 정확히 일치해야 합니다. 태그 CI는 macOS arm64·Windows x64/arm64 검증과 패키징이 모두 성공한 경우에만 자동 생성한 노트와 함께 GitHub Release를 공개합니다. 브랜치·PR CI는 발행 없이 artifact만 생성합니다. 업로드 실패 시 draft를 남겨 재시도하며 이미 공개된 Release는 덮어쓰지 않습니다. 버전·태그를 자동 생성하거나 앱을 자동 업데이트하지 않습니다.

## 번역 수정

`localization/`의 UTF-8 카탈로그 7개를 양쪽 네이티브 앱이 공유합니다. 모든 언어의 메시지 키와 이름 있는 치환값을 일치시키세요. 수정 후 `python3 scripts/localization.py`를 실행하고 카탈로그와 생성된 네이티브 테이블을 함께 커밋합니다. 제출 전 `python3 scripts/localization.py --check`와 `python3 -m unittest discover -s tests -p 'test_localization*.py'`로 검사합니다. 배포 ZIP에는 별도의 런타임 번역 파일이 필요하지 않습니다.
