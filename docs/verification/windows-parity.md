# Windows 기능 동등화 검증

기준은 [현재 명세](../dev-plans/current-spec.md)와 [승인된 Windows 동등화 명세](../dev-plans/specs/20261117-windows-macos-parity/spec.md)다. 아래 절차가 있다는 사실은 실행 완료를 뜻하지 않는다. 실제 결과는 해당 커밋·아키텍처의 CI evidence와 [반영 기록](../dev-plans/windows-catchup.md)에 남긴다.

## 자동 검증 범위

Windows x64·ARM64 네이티브 러너에서 각각 다음을 실행한다.

```powershell
pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture x64
# ARM64 러너에서는 -Architecture arm64
```

CTest는 설정·검증·연결 관리자·편집 모델·Windows 저장/프로세스를 검사한다. `ui-controller`는 실제 Win32 설정창·상태 모달·중복 실행 IPC를 격리된 설정과 주입 세션으로 검사한다. Python 통합 테스트는 GUI와 같은 production 연결 관리자를 시스템 OpenSSH 및 격리된 sshd로 실행한다. 테스트는 임시 설정·키·루프백 서버만 사용한다. 개발 PC에 SSH 서버를 설치하거나 실제 사용자 ssh-agent 서비스를 변경하지 않는다.

| 기존 v1 검증 의도 | 현재 v2 검증 |
|---|---|
| 실제 포워딩·상속 규칙·비활성 규칙 | 독립 호스트, Local/Remote/DynamicForward 데이터 전달, 실행 상태 |
| 첫 실패 재시도 | 접속 거부·조기 종료/리셋에만 옵션별 한 번; 인증·호스트 키·타임아웃 제외 |
| 재연결 시 최신 설정 | 저장값과 임시 실행값 구분, 명시적 저장과 전체 재연결의 초기화 |
| 단절 후 60초 재연결·종료 | 폐기된 정책. 5초 이벤트 복구와 65초 무단 재연결·자동 종료 없음으로 대체 |
| 종료 시 예약 취소 | 다중 호스트·조회 자식·진행 중 작업·늦은 콜백까지 정리 |
| 포트 충돌 독립성 | 네이티브 중복 바인딩 관측과 배타적 테스트 소켓에 의한 실패 검증을 분리 |
| ProxyJump 준비 판정 | 점프 성공·대상 지연/실패를 분리하고 정상 대상의 실제 데이터 전달도 검증 |
| 인증 키 보존·중복 등록 | 키 보존 자동 검사 유지; Windows→POSIX 실제 등록은 아래 별도 확인 |

`legacy-v1`은 구버전 재현용으로 남긴다. 현재 Windows 평가에서 실행하지 않는 옛 수명 정책 테스트를 새 기능 통과의 근거로 사용하지 않는다. macOS 전용 조회 취소 테스트와 Windows Job Object 테스트는 같은 정리 요구를 서로 다른 OS 구현에서 확인한다.

Windows OpenSSH 9.5p2에서는 서버가 클라이언트 식별 문자열을 읽지 않고 연결을 닫으면 `kex_exchange_identification: read: Unknown error`가 관측됐다. 이 문자열만으로 리셋을 확정할 수 없으므로 기존 미분류 오류 제외 정책에 따라 재시도하지 않는다. 재시도 통합 테스트는 식별 문자열을 읽은 뒤 FIN으로 조기 종료하여 명시적 종료 진단으로 옵션 ON/OFF·한 번 제한·지연을 검증한다. 일반 `Unknown error`를 재시도하도록 분류를 넓히지 않으며 코어 회귀 테스트로 제외를 확인한다.

## 실제 Windows 데스크톱 확인 절차

일반 사용자 권한과 시스템 OpenSSH Client 9.5 이상으로 테스트용 호스트와 서로 다른 로컬 포트를 사용한다. 구버전·미설치 환경에서는 설치/업데이트 안내만 나오고 설정·다른 연결이 보존되는지도 확인한다. 실제 사용자 설정을 변경할 때는 변경 대상을 확인하고 원본을 보관한다. 다음 결과를 Windows 버전, CPU, 앱 커밋, OpenSSH 버전과 함께 기록한다.

1. 설정 없음·정상 설정·손상 설정·`--open-config`의 시작 분기, 시작 OK/Cancel과 운용 중 OK/Cancel을 확인한다. 트레이가 계속 유지되고 손상 파일이 바뀌지 않아야 한다.
2. 두 호스트의 편집값을 각각 변경하고 전환·선택 저장·저장 없이 연결·취소한다. 다른 호스트의 초안과 기존 연결이 유지되는지 확인한다. 재연결 확인창에서 취소하면 연결을 끊지 않아야 한다.
3. 100%·150%·200% DPI, 작은 창, 다른 DPI 모니터로 이동한 상태에서 좌우 패널·고정 하단·파일 선택 버튼·명령 프리뷰를 확인한다. 키보드 Tab, Enter, Escape와 긴 오류/많은 규칙의 스크롤도 확인한다.
4. 연결 상태 팝업을 열어 둔 채 해당 SSH 연결을 종료·복구한다. 선택 호스트가 고정되고 실제 대상·상태·오류가 갱신되어야 한다. 팝업 닫기는 편집이나 연결 의도를 바꾸지 않아야 한다.
5. 설정창·트레이 메뉴·상태 팝업이 열린 각각의 상태에서 앱을 다시 실행한다. 트레이·설정·팝업이 중복되지 않고 초안이 유지되어야 한다. Explorer를 다시 시작하면 트레이가 복원되어야 한다.
6. 자동 연결 ON/OFF와 수동 끊기를 섞어 절전·복귀, LAN 단절·복구, 내부망 전용 환경과 VPN을 확인한다. 마지막 유효 이벤트 후 5초에 의도 ON의 끊어진 호스트만 복구되어야 한다. 전체 사용 가능 상태가 계속 유지되는 개별 어댑터 변경은 추가 복구 계기가 아니다.
7. 외부 인증 터미널에서 암호화된 기존 키·암호 없는 기존 키·새 키를 확인한다. ssh-agent가 준비되지 않았으면 안내가 나오며 UAC나 서비스 변경이 없어야 한다. 완료 후 다른 편집·연결을 유지하고 자동 연결하지 않아야 한다.
8. 서로 다른 로그인 세션에서 같은 사용자의 앱을 실행할 수 있고, 각 세션 안의 중복 실행은 합쳐지는지 확인한다. 공유 설정의 동시 저장에서 서로 다른 호스트가 사라지지 않아야 한다.

## 별도 인증 대상 검증

Windows CI의 네이티브 sshd는 원격 Linux/macOS 계정의 `authorized_keys` 등록 환경을 대신하지 않는다. 별도의 테스트용 Linux/macOS 계정에서 Windows 인증 도우미를 실행하여 다음을 확인한다.

- 선택한 개인키에서 유도한 공개키를 등록하고, 입력 없는 접속 확인 후 해당 호스트의 개인키 경로만 저장한다.
- 기존 주석·다른 키·동일 키의 제한 옵션을 보존하고 재실행해도 중복 등록하지 않는다.
- 호스트 키 변경·서버 정책·인증 실패를 우회하지 않고 실패 시 무조건 재시도하지 않는다.
- 도우미 실행 중 다른 호스트 저장·같은 호스트 편집·호스트 삭제가 일어나도 최신 데이터와 사용자 초안을 보존한다.

## 결과 구분

네이티브 빌드/자동 검사, Linux 교차 컴파일, 실제 데스크톱 확인은 서로 다른 증거다. 교차 컴파일만으로 Windows 실행 성공을 보고하지 않는다. 수동 절차와 Windows→POSIX 등록을 수행하지 않았다면 미검증으로 남긴다. 배포 ZIP 크기와 유휴 CPU/메모리는 측정 범위를 함께 기록하며 임의 합격 수치를 만들지 않는다.

## 현재 로컬 검증 상태 (2026-11-17)

Linux의 CMake/CTest에서 `core`, `manager`, `ui-model` 3종이 통과했다. LLVM-MinGW 20261104로 Windows x64·ARM64 실행 파일과 테스트 실행 파일의 컴파일·링크를 확인했다. 공통 Python 테스트 구문 검사와 `git diff --check`도 통과했다. macOS 소스·리소스·전용 스크립트 변경은 없다.

이 결과에 Windows 실행·MSVC 빌드·네이티브 SSH 통합·배포 ZIP·macOS 회귀 실행은 포함되지 않는다. 세 네이티브 CI 작업과 전체 변경 독립 리뷰가 끝나기 전에는 검증·통합 완료로 처리하지 않는다.
