# 설정창·트레이 개선 검증

[기능 명세](../dev-plans/specs/20261117-settings-tray-refinement/spec.md)의 설정창, 규칙 모달, 호스트 설명과 트레이 표시를 검증한다. 기존 SSH·복구·인증 보안 검사는 유지한다.

## 자동 검사

- macOS ARM64: `bash scripts/eval-macos.sh`
- Windows x64: `pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture x64`
- Windows ARM64: `pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture arm64`

설정 파서·직렬화의 description 누락/null/빈 값/한글/잘못된 타입/개행, 설명만 변경한 실행 설정 비교, 선택 저장·인증 키 변경 시 설명 보존을 검사한다. 공통 SSH 통합 검사의 설정 입력 사례에도 설명을 포함한다.

규칙 편집 버퍼는 확인 시에만 초안을 변경하고 취소 시 원본을 보존해야 한다. 포트 범위·활성 규칙 중복·미완성 호스트의 규칙 작성·기존 규칙 ID 보존을 확인한다. 메뉴 표시 모델은 비활성 규칙과 상속 규칙, 실행 전·현재/마지막 실행·부분 실패·설정 차이·빈 목록을 검사한다.

## Windows 실기기 확인

실제 사용자 설정과 연결을 변경하지 않는 격리된 테스트 데이터를 사용한다. 사용 중인 앱을 임의 종료하거나 인증·서비스·OS 배율 설정을 변경하지 않는다.

1. 기본 크기와 작은 작업 영역에서 이름/설명/SSH 주소 순서, 고정 OK/Cancel(Windows는 왼쪽부터 확인·취소), 입력·버튼·스크롤의 접근성을 확인한다. 100/150/200% 배율의 검증 방식과 실제 모니터 배율 여부를 결과에 구분한다.
2. 새 규칙 취소 시 행이 추가되지 않아야 한다. 확인 시에만 한 행이 추가되고, 편집 버튼·더블클릭이 같은 모달을 열어야 한다. 규칙 모달 하단에 상시 오류 표시 영역이 없어야 한다. 잘못된 포트와 중복 포트는 모달 소유의 경고 대화상자로 알리고 경고를 닫으면 입력값과 규칙 편집창이 유지되어야 한다.
3. 규칙 모달에서 Escape·닫기·중복 실행을 확인한다. 부모 선택과 초안이 유지되어야 한다.
4. 상시 로그 영역과 저장 성공 팝업이 없어야 한다. 실패 경고와 기존 연결 상태 팝업의 오류·실행 설정 정보는 유지되어야 한다.
5. 트레이 hover에서 앱 이름·연결/미연결 수가 보여야 한다. 상위 메뉴와 호스트 동작의 아이콘, SSH 기준의 호스트 세 상태 아이콘, 규칙별 정보·상태·구분선 순서를 확인한다. SSH 연결 상태에서 일부 규칙이 실패해도 호스트는 연결됨 아이콘이고 경고 문구가 없으며 해당 규칙 아이콘만 실패를 표시해야 한다.
6. 열린 메뉴에서 준비·실패·단절 상태가 갱신되고 불필요하게 메뉴가 닫히지 않아야 한다. 긴 주소·여러 규칙과 비활성·상속 규칙도 확인한다.

## 결과 기록

2026-11-17, 로그인 자동 시작이 추가된 main `5342750`에 재통합한 `f5f3b61`에 대해 [네이티브 CI 44035919838](https://github.com/GuruJung/LocalForwarder/actions/runs/44035919838)가 세 플랫폼 모두 성공했다.

- macOS ARM64: 실제 AppKit 창의 900×650 → 800×430 → 900×650 재확대와 520×360 작업 영역 상당의 480×290 창, 컨트롤 가시성·스크롤 접근·규칙 모달 검사를 통과했다. Swift 검사 50개와 실제 로그인 항목 등록 fixture 통과, 실제 SSH 통합 검사 15개 통과·Windows 전용 검사 1개 제외, 서명 검증과 ZIP 생성 성공.
- Windows x64·ARM64: 각각 CTest 7개 통과, 실제 SSH 통합 검사 14개 통과·macOS 쿼리 종료 및 POSIX 서버 인증 등록 2개 제외, ZIP 생성 성공. 제외 항목은 기존 플랫폼 범위이며 동등성 검증으로 간주하지 않는다.
- 이 Windows VM에서 `f5f3b61` CI x64 배포 파일의 `--test-ui`가 종료 코드 0으로 완료됐다(2.174초). 96/144/192 DPI를 코드에서 모의하여 기본/작은 작업 영역, 창·버튼 경계, 포커스 스크롤, 규칙 모달·취소·입력 오류 보존과 Windows 확인·취소 순서를 확인했다. 실제 OS 배율을 100/150/200%로 바꾸는 수동 검사는 하지 않았다.
- 사용자 화면 확인: OS 자동 DPI에서 글자 크기 정상, 소형 설정창과 새 규칙·편집·취소, 트레이 hover 툴팁, 기능 아이콘, SSH 기준 호스트 세 상태와 개별 규칙 상태를 확인했다. 최종 규칙 팝업의 상시 오류 영역 제거, 확인·취소 순서, 잘못된 포트의 경고와 입력 유지도 사용자가 정상으로 확인했다. 화면 자동화의 데스크톱 접근 오류 때문에 직접 도구 관찰 대신 사용자 관찰을 기록했다.
- 화면 확인은 `d5b3779` CI 패키지와 `ec58ca4` 동일 소스의 x64 교차 빌드에서 이루어졌으며, 해당 MSVC CI 패키지는 위 네이티브 UI 검사로 다시 확인했다. 최신 main의 로그인 자동 시작을 결합한 `f5f3b61`에서 양쪽 전체 CI와 이 Windows 호스트의 배포 파일 UI 검사를 다시 통과했다. 기존 설정·규칙·트레이 표시의 수동 관찰은 재통합 전 확인한 증거이며, 로그인 메뉴와의 결합은 코드 검토·네이티브 검사로 확인했다. 실제 로그인/로그아웃 수동 검사는 수행하지 않았다. 실제 사용자 SSH 연결·설정은 사용하지 않았다. 미리보기의 실패 규칙은 표시 검증용 가상 상태다.
- macOS 실기기 시각 검증은 승인된 범위에 따라 미수행이다. Windows의 실제 OS DPI 변경, Explorer 재시작, 물리 네트워크·절전·외부 인증 터미널은 이번 화면 확인의 증거에 포함하지 않는다.

검증 중 발견한 작은 작업 영역에서의 고배율 최소 창 크기 초과는 실제 배치 코드를 수정하고 경계 검사를 유지해 해결했다. 기존 SSH 재연결 통합 검사에서 이전 연결 알림을 새 연결 완료로 받을 수 있는 경합도 확인하여 `connecting → connected` 전환을 기다리도록 보강했다. 전달 성공·이전 포트 종료 검사는 유지했고, 위 최종 CI에서 전체 평가를 다시 통과했다.

독립 리뷰에서 확인한 macOS의 좁은 폼 잘림은 입력·옵션·버튼의 세로 재배치와 좁은 창의 상단 호스트 목록으로 보완했다. 네이티브 검사에서 발견한 재확대 시 문서 폭 불일치는 세로 스크롤바 공간을 유지하여 해결했다. 위 최종 AppKit 검사에서 기본·축소·재확대·아주 좁은 창을 모두 통과했으며, 이를 macOS 실기기 시각 검증으로 간주하지 않는다.

사용자는 macOS 실기기 검증을 나중에 직접 수행하고 자동 검사 실패가 남으면 상태를 명시해 나머지를 진행하도록 요청했다. 최종 재통합 CI는 실제로 통과했으므로 실패한 검사를 면제하거나 성공으로 바꿔 기록하지 않았다.
