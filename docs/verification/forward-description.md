# 포워딩 규칙 설명 검증

[기능 명세](../dev-plans/specs/20261117-forward-description/spec.md)에 따라 저장 호환성과 설정창 편집을 검사한다.

## 자동 검사

- `bash scripts/eval-macos.sh`
- `pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture x64`
- `pwsh -NoProfile -File scripts/eval-windows.ps1 -Architecture arm64`
- 기존 v1/v2의 필드 누락, null, 빈 문자열, 한글 문자열을 읽고 빈 설명은 저장 시 생략한다. 잘못된 타입과 개행·NUL을 거부하며 읽기 실패 시 원본을 보존한다.
- 선택 저장·다른 호스트 저장·인증 키 갱신에서 설명을 보존하고 v1 최초 저장 백업을 유지한다.
- 규칙 확인·취소·설명 삭제·ID와 순서·미저장 판단을 검사한다. SSH 명령과 실행 설정 비교 및 기존 트레이·연결 상태 표현은 설명에 영향받지 않는다.

## 화면 확인

Windows의 격리된 테스트 설정에서 설명 입력과 목록의 마지막 열, 작은 창과 긴 한글 설명을 확인한다. 실제 사용자 설정·현재 연결은 변경하지 않는다. macOS 자동 검사와 실제 기기 수동 검증을 구분한다.

## 실행 결과

- 코드 커밋 `467e4bf9641ebc542a3b7587630fe3a768fcf497`, 2026-11-17 [전체 CI](https://github.com/GuruJung/LocalForwarder/actions/runs/44047461439) 통과.
- macOS 15 Apple Silicon: Swift 테스트 56개(새 설명 테스트 6개 포함), 실제 AppKit 레이아웃·규칙 편집 검사, SSH 통합 검사 및 패키징 통과. 기본 900×650, 800×430, 520×360 작업 영역으로 축소된 480×290 설정창과 규칙 시트를 검사했다.
- Windows x64·ARM64: 각 CTest 7개, 네이티브 규칙 모달·목록·100%/150%/200% DPI 검사, SSH 통합 검사 및 패키징 통과. 이 Windows 호스트에서도 x64 네이티브 7개 검사를 별도로 통과했다.
- 공통 SSH 통합 검사는 플랫폼별 16개이며 기존 제외는 macOS 1개, Windows 2개다. Windows 제외는 macOS Foundation 종료 회귀 검사와 POSIX 서버 대상 인증 등록이고, macOS 제외는 Windows Job Object 종료 검사다. 새 v1/v2 설명 호환 사례 28개는 모두 실행했으며 실패·오류는 없다.
- 설명의 한글 저장·재읽기, 누락/null/빈 값·잘못된 타입·개행/NUL, 빈 필드 생략, v1 원본 보존·백업, 선택 저장·인증 갱신, ID·순서 보존, 설명만 변경할 때 SSH 인수와 실행 비교의 불변을 확인했다.
- 네이티브 UI 자동 검사에서 입력·목록 반영·추가·편집·취소·Escape·설명 삭제와 좁은 창의 컨트롤 배치를 확인했다. AppKit 시트에는 닫기 버튼이 없어 실제 `windowShouldClose` 처리 계약을 검사했으며, 사용자 닫기 버튼 클릭을 수행했다고 주장하지 않는다.
- 실제 기기의 육안 UI 확인은 양쪽 모두 미완료다. Windows 격리 미리보기 창은 화면 제어 도구에서 발견되지 않았고 사용자도 창이 보이지 않는다고 확인했다. 테스트 프로세스는 종료했다. 실제 사용자 설정과 연결은 변경하지 않았다.
- 초기 macOS CI의 실패는 추가 입력란 수와 AppKit 시트 닫기/확인 키 값에 대한 새 테스트 가정 때문이었다. 컨트롤 목록을 갱신하고 실제 취소·확인 처리 및 초안·파일 보존 결과로 검증했다. 기능 이전의 검사나 플랫폼별 CI를 제거·완화하지 않았다.
- 마지막 변경 이후 `git diff --check` 통과. 이 결과 기록만 바뀌는 문서 커밋에서는 위 코드 커밋의 네이티브 결과를 재사용한다. 소스·테스트·평가 스크립트·CI·패키지에 들어가는 README는 동일하다.
