## Tracked Feature Spec

### 목적과 지원 범위

시스템 OpenSSH를 실행하고 관리하는 작은 네이티브 GUI 프로그램을 만든다. SSH 프로토콜과 포워딩 전송 기능은 직접 구현하지 않는다.

- macOS 15 이상 Apple Silicon 지원.
- Windows 11 x64·ARM64 지원.
- `GuruJung/LocalForwarder` 공개 GitHub 저장소와 MIT 라이선스 사용.
- 호스트별 포워딩 설정, 독립적인 다중 실행, 상태 표시, 자동·수동 재연결, 인증 설정 지원 제공.
- 유휴 상태에서 주기적인 포트 검사·프로세스 목록 조회·화면 갱신을 하지 않는다.
- 설치 프로그램, 자동 업데이트, 로그인 시 자동 실행, 목적지 서비스 상태 검사는 첫 버전에서 제외한다.

### 실행과 설정

- 실행할 때마다 저장된 호스트 목록에서 접속 대상을 선택한다. 인스턴스 하나는 호스트 하나와 그 포워딩 규칙들을 담당한다.
- 호스트 추가·수정·삭제와 규칙별 활성화 선택을 제공한다.
- 접속 대상은 SSH 별칭 또는 실제 주소를 같은 입력란에 받는다. 사용자명·SSH 포트·개인키 경로는 선택 항목이며, 미입력 항목은 SSH 설정에 맡긴다.
- 앱 규칙은 로컬 포트, 원격 목적지 호스트, 목적지 포트, 활성화 여부로 구성한다. 앱이 만드는 포트는 `127.0.0.1`에 바인딩한다.
- 기존 SSH 설정의 포워딩은 읽기 전용으로 보여주고 그대로 함께 실행한다. 기존 규칙의 바인딩 주소와 포워딩 종류는 SSH 설정을 따른다.
- 빈 필수 항목, 잘못된 포트, 활성 앱 규칙 간 로컬 포트 중복 등 명백한 입력 오류는 UI에서 표시한다.
- 실제 포트 점유와 호스트 중복은 사전 검사하지 않는다. SSH의 실행 결과로 처리한다.

### 설정 저장

- 두 OS 모두 실제 사용자 홈의 `.LocalForwarder/config.json`을 사용한다.
- 설정 화면을 열 때와 최초 연결·자동 재연결·수동 재연결 직전에 파일을 다시 읽는다.
- 저장은 즉시 수행하며, 변경 충돌 감지나 병합 UI는 제공하지 않는다. 동일 항목은 마지막 저장 결과를 따른다.
- 파일이 없으면 최초 실행으로 처리한다. 파일을 읽을 수 없거나 JSON이 손상되면 오류를 표시하고 기존 파일을 보존한다.
- 연결 중 설정을 저장하면 ‘다음 연결부터 적용’ 또는 ‘연결을 끊고 재연결’을 선택하게 한다. 기존 연결은 재연결 전까지 현재 설정으로 유지된다.
- ‘다음 연결’에는 자동 재연결도 포함한다. 재연결 시 호스트가 삭제되었거나 설정이 잘못되어 있으면 실패 원인을 기록하고 종료 대기 상태로 전환한다.

### 연결과 재연결

일반 연결에서는 콘솔 창, 비밀번호 입력, 호스트 키 확인 대화상자를 띄우지 않는다. 모든 연결 작업은 첫 실패 후 1초 뒤 한 번 더 시도하며, 두 번째도 실패하면 최종 실패로 판단한다.

| 상황 | 동작 |
|---|---|
| 최초 연결 성공 | 창을 숨기고 `connected` 아이콘 표시 |
| 최초 연결 최종 실패 | 원인을 표시하고 사용자 확인 후 종료 |
| 연결 중 비의도적 단절 | `disconnected`로 전환하고 자동 재연결을 60초 뒤 예약 |
| 자동 재연결 대기 만료 | 자동 재연결 작업을 한 차례 수행 |
| 재연결 성공 | `connected`로 복귀하고 모든 대기 타이머 취소 |
| 자동·수동 재연결 최종 실패 | 실패 원인을 기록하고 그 시각부터 60초 뒤 종료 |
| 대기 중 사용자가 재연결 선택 | 예정된 자동 재연결·종료를 취소하고 즉시 수동 재연결 |
| 사용자가 종료 선택 | 모든 예약을 취소하고 소유한 SSH를 정리한 뒤 종료 |

- 자동 재연결 작업도 첫 실패 후 1초 뒤 한 번 재시도하므로 실제 SSH 실행은 최대 두 번이다.
- 자동 재연결 최종 실패 후에는 추가 자동 재연결을 예약하지 않는다. 종료 대기 중에는 수동 재연결이 가능하다.
- 수동 재연결은 예정된 자동 재연결을 대신한다. 수동 재연결 실패 후에도 다시 자동 재연결을 예약하지 않는다.
- 재연결 성공 이후 다시 단절되면 새로운 자동 재연결 주기를 시작한다.
- 재연결 중에는 종료 타이머를 멈추고 중복 재연결 요청을 막는다.
- 설정 적용을 위한 의도적인 SSH 종료는 비의도적 단절로 취급하지 않는다. 사용자가 선택한 즉시 재연결만 실행한다.
- 여러 포워딩 중 하나라도 개설에 실패하면 전체 연결을 실패 처리한다. 포트 충돌은 해당 포트가 이미 사용 중임을 알린다.
- `connected`는 SSH 연결과 요청된 포워딩 개설의 성공을 의미한다. 개별 목적지 서비스의 응답 여부는 검사하지 않는다.

### 트레이와 절전

- 연결 성공 이후 인스턴스별로 별도의 트레이 아이콘을 표시한다. 툴팁에 호스트와 상태를 표시한다.
- 연결 중 메뉴는 ‘설정’, ‘종료’만 제공한다.
- 단절 후 자동 재연결 대기와 종료 대기 중에는 ‘재연결’을 추가한다. 재연결 실행 중에는 중복 실행할 수 없게 한다.
- 자동 재연결 실패 시 창이나 외부 터미널을 자동으로 띄우지 않는다. 실패 원인은 설정 화면에서 확인할 수 있게 하며 종료 타이머는 계속 진행한다.
- 최초 설정 중에는 자동 재연결·종료 타이머를 적용하지 않는다.
- 연결 단절 시각은 앱이 단절을 감지한 시각으로 정의한다.
- 절전 중 경과한 시간을 대기 시간에 포함한다. 복귀 시 자동 재연결 예정 시각이 지났으면 한 차례 재연결하고, 종료 예정 시각이 지났으면 종료한다.
- 아직 연결 상태인 채 복귀한 경우에는 SSH의 생존 판정을 따르고, 단절을 감지하면 일반 단절 흐름으로 들어간다.

### 외부 터미널 인증 설정

- 최초 연결 실패 중 터미널에서 해결 가능한 인증·호스트 검증 문제는 원인과 수행할 행동을 설명한다.
- 안내 확인 후 외부 터미널에서 복구 도우미를 실행하고 GUI 인스턴스를 종료한다.
- 자동 재연결 실패 후에는 사용자가 설정 화면에서 인증 복구를 선택할 때 동일한 흐름을 수행한다. 복구 전환 시 모든 예약을 취소한다.
- 사용 가능한 기존 키를 우선 사용한다. 키가 필요하면 암호 없는 새 키를 만들고 원격 계정에 공개키를 등록하도록 지원한다.
- 비밀번호와 기존 개인키 암호는 외부 터미널에서만 입력하며 앱 설정에 저장하지 않는다.
- 자동 공개키 등록은 일반적인 Linux·macOS OpenSSH 계정을 대상으로 한다. 기존 공개키를 보존하고 같은 키를 중복 등록하지 않는다.
- 서버가 공개키 인증을 금지하거나 추가 인증을 요구하면 제한을 설명한다. 서버 인증 정책이나 변경된 호스트 키를 자동으로 우회하지 않는다.
- 설정 완료 후 비대화형 접속을 검증하고 사용자가 앱을 다시 실행하도록 안내한다.

### 사용자 결정 기록

| 주제 | 선택 및 적용 범위 | 명시된 이유·절충 |
|---|---|---|
| 제품 구조 | 시스템 SSH의 GUI wrapper, 작은 용량과 낮은 CPU 사용 | 사용자가 직접 제시한 우선순위 |
| 호스트 선택 | 매 실행마다 선택, SSH 별칭 우선 | 추가 이유 미제시 |
| 규칙 | 개별 활성화, 하나라도 개설 실패하면 전체 실패 | 추가 이유 미제시 |
| 다중 실행 | 인스턴스별 아이콘, 실제 포트 충돌에 맡김 | 사전 중복 검사로 로직이 복잡해지는 것을 피함 |
| 상태 판정 | SSH 연결 상태만 사용 | 서비스 장애 검사로 로직이 복잡해지는 것을 피함 |
| 연결 작업의 재시도 | 첫 실패 후 1초 뒤 한 번 재시도 | 처음 접속을 끊는 서버를 지원해야 함 |
| 자동 재연결 | 비의도적 단절 후 1분 뒤 시도, 최종 실패 후 1분 뒤 종료 | 일시적인 네트워크 단절에서 자동 복구 |
| 수동 재연결 | 대기 중 제공, 최종 실패 후 다시 1분 | 추가 이유 미제시 |
| 설정 변경 | 다음 연결 적용 또는 즉시 재연결 선택 | 추가 이유 미제시 |
| 파일 저장 | 홈의 `.LocalForwarder/config.json`, 매번 읽기, 즉시 저장, 충돌 검사 없음 | 사용자 지정 |
| 접속 범위 | 앱 규칙은 내 컴퓨터에서만 사용 | 추가 이유 미제시 |
| 인증 지원 | 키 생성·등록 지원, 새 개인키는 암호 없이 생성 | 추가 이유 미제시 |
| 기존 SSH 규칙 | 기존 포워딩도 함께 적용, 읽기 전용 표시 | 추가 이유 미제시 |
| 플랫폼·기술 | macOS 15+ ARM64의 Swift/AppKit, Windows 11 x64·ARM64의 C++/Win32 | 제안 승인 및 Windows ARM64 추가 요청 |
| 빌드·배포 | 공개 저장소, 무료 GitHub 빌드 활용, 무료 ZIP 배포 | Windows에 빌드 도구가 없으며 비용 부담을 피하고자 함 |
| 저장소 | `GuruJung/LocalForwarder`, 공개, MIT | 사용자 지정 |

자동 대기를 수동 재연결이 대체하는 규칙, 절전 중 시간 계산, 자동 실패 시 창을 띄우지 않는 처리는 위 요구사항을 일관되게 구현하기 위한 기본 동작으로 정한다.

### 수용 기준

- 세 플랫폼 산출물이 각각 네이티브 빌드되고 실행된다.
- 별칭·직접 주소·선택적 접속 옵션과 여러 활성 규칙이 올바르게 전달된다.
- 정상 연결, 첫 실패 후 성공, 연속 실패, 일부 포트 충돌이 명세와 일치한다.
- 비의도적 단절 후 60초에 자동 재연결하고, 최종 실패 후 60초에 종료한다. 자동 재연결이 무한 반복되지 않는다.
- 수동 재연결·설정 적용·사용자 종료·절전 복귀가 중복 SSH 실행이나 남은 타이머를 발생시키지 않는다.
- 동일·상이한 호스트를 여러 인스턴스로 실행해도 다른 인스턴스의 SSH를 종료하지 않는다.
- 일반 연결 중 콘솔이나 입력 프롬프트가 나타나지 않는다.
- 설정 재열기와 재연결에 디스크의 최신 값이 반영되고, 저장 실패·손상 파일이 기존 설정을 파괴하지 않는다.
- 외부 터미널에서 키 등록 후 입력 없는 접속을 검증할 수 있다.
- 유휴 상태에서 busy loop가 없으며, 플랫폼별 배포 크기·유휴 CPU·메모리 측정 결과를 보고한다. 임의의 수치 목표를 통과 조건으로 만들지는 않는다.

### Current Spec Impact

`add`: 현재 명세가 없으므로 `docs/dev-plans/current-spec.md`를 한국어로 생성한다. 이 기능에서 결정된 지원 플랫폼, 저장 형식, 사용자 흐름, 자동·수동 재연결, 오류·인증 복구, 기존 SSH 설정과의 관계, 배포 범위를 현재 의도로 기록하고 이 기능 명세를 연결한다.
