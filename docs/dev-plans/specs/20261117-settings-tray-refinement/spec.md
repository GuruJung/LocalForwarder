# Tracked Feature Spec

## 목표와 범위

macOS와 Windows의 설정창을 작고 읽기 쉽게 정리하고, 규칙 편집을 모달로 분리한다. 트레이 메뉴는 SSH 요약과 포워딩별 상태를 중심으로 구성한다. Windows의 툴팁 누락과 메뉴 아이콘 미구현을 수정한다.

기존 SSH 연결·재시도·자동 복구·선택 호스트 저장·임시 실행 설정 정책은 유지한다. 설정창 조작이나 상태 조회만으로 연결을 변경하지 않는다.

## 사용자 동작

### 설정창과 오류 안내

- 기본 크기는 약 **900×650 논리 단위**를 기준으로 한다. 시스템 글꼴 크기를 유지하고 여백과 배치를 줄인다. 화면 작업 영역에 맞춰 축소하며 작은 화면에서는 오른쪽 폼을 스크롤한다.
- 이름·설명·SSH 별칭/주소 순서로 배치한다. 일반 너비에서 사용자명과 SSH 포트, 개인키와 파일 선택 버튼은 각각 같은 행을 사용한다. 화면이 좁으면 입력·옵션·버튼을 여러 행으로 재배치하여 잘림을 피하고 스크롤로 접근한다.
- 포워딩 목록과 읽기 전용 명령 프리뷰를 유지한다. 확인·취소 버튼은 하단에 고정한다. 버튼의 왼쪽부터 순서는 Windows에서 확인·취소, macOS에서 취소·확인이다.
- 설정 폼의 상시 상태·검증 메시지 위젯을 제거한다. 저장 성공 팝업은 추가하지 않고 미저장 표시 해제로 저장 결과를 알린다.
- 입력 검증·파일 읽기·저장·인증 준비 등 작업 실패는 경고 대화상자로 알린다. 규칙 모달에도 상시 오류 표시 영역을 두지 않는다. 규칙 입력 오류는 해당 모달 소유의 경고 대화상자로 알리고 편집 모달과 입력값을 유지한다.
- 비동기 SSH 상태·최근 오류·목적지 오류·실행 설정 차이는 기존 `연결 상태…` 팝업에서 확인한다. 상태 변화마다 경고 팝업을 띄우지 않는다.

### 규칙 추가와 편집

- 양쪽 플랫폼의 버튼을 `새 규칙…`, `규칙 편집…`, `규칙 삭제`로 통일한다. 선택 규칙의 더블클릭도 편집 모달을 연다.
- Windows의 하단 규칙 입력란을 제거하고 macOS의 포트·목적지 셀 직접 편집도 모달로 통일한다. 목록의 사용 체크박스는 유지한다.
- 모달에는 사용 여부·로컬 포트·목적지 호스트·목적지 포트를 제공한다. 신규 기본값은 기존과 같은 활성, `8080 → localhost:80`이다.
- 확인 시 검증한 규칙을 선택 호스트의 초안에 추가하거나 교체한다. 파일 저장이나 연결은 하지 않는다. 편집 시 규칙 ID와 목록 순서를 유지한다.
- 취소·Escape·창 닫기는 모달의 변경만 버린다. 모달이 열린 동안 부모 설정창 조작과 호스트 전환을 막고, 중복 실행은 기존 모달을 앞으로 가져온다.
- 포트 범위·목적지·활성 규칙의 중복 로컬 포트를 검증한다. 아직 이름이나 SSH 주소를 입력하지 않은 신규 호스트에서도 규칙을 작성할 수 있다.

### 트레이 표시

- Windows 아이콘에 마우스를 올리면 기존 명세대로 앱 이름·연결 수·미연결 수가 표시된다.
- 설정·전체 재연결·종료와 호스트별 연결/재연결·끊기·호스트 설정에 기능을 나타내는 아이콘을 제공한다.
- 호스트 행은 상태 아이콘과 이름을 사용하며 `connected`, `disconnected`, `disabled` 문자열을 붙이지 않는다. 연결 작업 중·임시 실행 여부는 텍스트로 구분 가능하게 유지한다. 호스트 행에 포워딩 경고 문구를 붙이지 않는다.
- 호스트 상태 아이콘은 SSH 기준의 연결됨(`connected`), 미연결(`disconnected`), 자동 연결 꺼짐(`disabled`) 세 상태만 사용한다. SSH가 연결되면 자동 연결 옵션이나 개별 포워딩 실패와 무관하게 연결됨 아이콘을 사용하고, 미연결이면 자동 연결 ON/OFF에 따라 미연결/자동 연결 꺼짐 아이콘을 사용한다. 작업 중에도 이 세 상태 기준을 유지한다. 포워딩 경고는 호스트 아이콘에 합치지 않고 서브메뉴의 개별 규칙 상태 아이콘으로 표시한다. 색상뿐 아니라 모양도 다르게 한다.
- 호스트 서브메뉴 순서는 다음과 같다.

  1. 클릭할 수 없는 SSH·포워딩 상태 요약
  2. 구분선
  3. 규칙별 포워딩 정보와 준비 상태 아이콘
  4. 구분선
  5. 기존 연결/재연결·끊기·호스트 설정 동작

- `최근 오류 없음`, `저장된 설정 사용`, `관측된 목적지 오류 없음`을 포함한 기존 부가 설명 행은 제거한다. 실제 상세 정보는 연결 상태 팝업에서 유지한다.
- 실행 이력이 있으면 현재·마지막 실행 설정의 앱 규칙과 관측한 SSH 상속 규칙을 사용한다. 실행 이력이 없으면 저장된 앱 규칙을 표시한다. 미저장 편집값을 실행 상태처럼 표시하지 않는다.
- 비활성 앱 규칙도 표시하되 별도 비활성 아이콘을 사용한다. 실행 중 저장 설정이 바뀌어도 실행 규칙과 새 저장 규칙을 혼합하지 않는다.
- 규칙 상태는 준비 중·준비됨·개설 실패·연결 끊김·확인 불가·비활성을 구분한다. 연결 전 활성 규칙은 미연결로 표시한다.
- 규칙 행은 조회용이며 클릭 동작을 추가하지 않는다. 앱 규칙과 SSH 상속 규칙의 출처를 구분하고, 규칙이 없으면 `포워딩 규칙 없음` 한 행을 표시한다.
- 메뉴를 열어 둔 상태에서도 상태를 갱신하며 선택 위치를 불필요하게 초기화하거나 메뉴를 닫지 않는다. 메뉴 표시를 위해 SSH 조회나 목적지 검사를 추가하지 않는다.

### 호스트 description과 호환성

- 호스트 JSON에 선택 문자열 `description`을 추가하고 설정 버전 2를 유지한다.
- 양쪽 플랫폼에서 이름과 SSH 주소 사이에 `설명 (선택)` 한 줄 입력란을 제공한다. 트레이 메뉴에는 설명 행을 추가하지 않는다.
- 누락·`null`·빈 문자열은 설명 없음으로 읽고, 빈 값은 저장 시 생략한다. 한 줄 텍스트로 취급하며 개행과 NUL은 거부한다.
- 설명은 SSH 인수나 인증 정보로 사용하지 않는다. 설명만 저장해도 현재 연결을 유지하며, 설명 차이만으로 실행 연결 설정이 다르다는 경고를 만들지 않는다.
- 설명을 미저장 판단·선택 저장·재읽기·인증 도우미의 선택 필드 갱신에서 보존한다.
- 기존 v1/v2 설정과 v1 최초 저장 백업 정책을 유지한다. 구버전 앱에서 다시 저장하면 새 설명 필드가 유실될 수 있다는 제한을 문서화한다.

## 사용자 결정

| 주제 | 선택 | 이유와 적용 범위 |
|---|---|---|
| 플랫폼 | macOS·Windows 모두 적용 | 별도 이유 미제시 |
| 창 크기 | 읽기 편한 소형, 약 900×650 | 작은 크기와 보기 좋은 구성을 요청 |
| 규칙 편집 | 편집 버튼과 더블클릭으로 모달 열기 | 팝업으로 분리하면 더 깔끔하다는 의견 |
| 설명 | 한 줄, 설정창에만 표시 | 연결과 포워딩 용도를 사람이 이해하도록 설명 |
| 트레이 규칙 | 비활성 규칙도 포함 | 별도 이유 미제시 |
| 호스트 아이콘 | SSH 세 상태만 표시 | Windows 미리보기 확인 후 양쪽 모두 호스트 경고 문구·경고 아이콘을 제거하고 개별 포워딩 아이콘으로 문제를 확인하도록 결정 |
| 오류 안내 | 실패할 때만 팝업, 규칙 오류도 경고 대화상자 | Windows 확인 후 규칙 모달의 상시 오류 영역을 제거하도록 결정 |
| 확인·취소 순서 | Windows 확인·취소, macOS 취소·확인 | 각 플랫폼의 기본 순서를 따르도록 요청 |
| 완료 검증 | 양쪽 CI·독립 리뷰·Windows 실기기 | macOS 실기기 시각 검증은 미수행으로 명시 |

## Current Spec Impact

`docs/dev-plans/current-spec.md` 전체의 한국어와 변경하지 않는 기존 의도를 보존한다.

- **replace:** 설정창 기본 배치와 포워딩 편집을 소형 창·규칙 모달 방식으로 변경한다.
- **remove:** 설정 폼의 상시 메시지 영역과 트레이의 부가 오류·실행 설정 설명 행을 제거한다. 오류 기록 기능 자체는 유지한다.
- **add:** 실패 안내 위치, 규칙 모달의 확인·취소·중복 실행 동작을 명시한다.
- **replace:** 호스트와 포워딩 상태를 아이콘으로 나타내고 규칙별 행을 제공하는 트레이 구성을 명시한다.
- **add:** 선택적 호스트 `description`의 용도·저장 호환성을 명시한다.
- 툴팁 내용과 SSH 정책은 유지한다. 플랫폼별 반영 기록에는 구현·자동 검증·실기기 검증을 구분하여 기록한다.

## 수용 기준

- 양쪽 설정창에서 주요 입력과 버튼이 읽기 쉽게 배치되고 작은 화면에서도 겹침 없이 접근된다.
- 규칙 추가·편집의 확인과 취소가 초안에 정확히 반영되며 다른 호스트·저장 파일·연결을 부당하게 변경하지 않는다.
- 상시 로그 위젯을 제거해도 작업 실패와 연결 상세 정보를 확인할 수 있다.
- Windows 툴팁과 양쪽 메뉴 아이콘·서브메뉴 순서·규칙별 상태가 위 요구사항과 일치한다.
- 비활성·상속·미연결·부분 실패 규칙을 구분하고 준비됨을 목적지 서비스 정상으로 해석하지 않는다.
- 설명이 양쪽 플랫폼 사이의 읽기·저장과 인증 설정 갱신에서 보존되고 기존 설정을 계속 읽을 수 있다.
