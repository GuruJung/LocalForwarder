# Tracked Feature Spec

## 목표와 범위

Windows LocalForwarder의 기능과 조작 흐름을 그대로 유지하면서 정렬·여백·배경·글꼴 위계를 통일한다. 설정창, 규칙 편집창, 연결 상태창, 트레이 메뉴와 아이콘, About 및 확인·오류 대화상자를 대상으로 한다.

기존 Windows 네이티브 컨트롤과 OS 기본 표현을 유지한다. macOS 변경, 새 기능, 설정 형식 변경, 문구 번역·이름 변경, 새 테마·다크 모드, UI 프레임워크 교체는 포함하지 않는다.

## 시각적 요구사항

- **라벨 정렬:** 이름·설명·SSH 대상 등 한 줄 라벨을 대응 입력 행의 세로 중앙에 배치한다. 규칙 편집창에도 같은 기준을 적용한다. 좁은 창의 위아래 배치에서는 라벨과 입력 사이의 간격을 일정하게 유지한다.
- **배경 통일:** 흰 폼 위에 라벨·체크박스마다 회색 사각형이 붙는 현상을 없앤다. 입력 가능한 영역과 읽기 전용 영역은 구분하되, 배경색 조각으로 화면이 분절되지 않게 한다.
- **간격과 크기:** 같은 역할의 입력창·버튼 높이, 행 간격, 구역 간 여백, 좌우 기준선을 통일한다. 현재 사이드바·설정 폼·고정 하단 버튼 구조와 약 900×650 논리 단위의 기본 크기를 유지한다.
- **텍스트와 정보 위계:** 본문 글꼴의 가독성을 유지한다. 구역 제목은 절제된 굵기 차이로 구분하고, 명령 프리뷰는 코드에 적합한 고정폭 글꼴을 사용한다. 한글·영문 혼합, 긴 설명과 경로가 겹치거나 잘려 접근 불가능해지지 않아야 한다.
- **팝업:** 규칙·연결 상태창의 라벨, 제목, 목록, 닫기 버튼에 같은 정렬·간격 원칙을 적용한다. About과 확인·오류 창은 네이티브 대화상자를 유지한다.
- **트레이:** 기존 아이콘의 의미·색상·형태와 메뉴 순서는 유지한다. 아이콘의 크기·내부 여백·선 두께·텍스트와의 정렬만 조화롭게 보정한다. 앱 로고를 새로 디자인하지 않는다.
- **접근성과 배율:** 포커스 표시, 선택·비활성 상태, 고대비 환경의 식별 가능성을 보존한다. 미관을 위해 글씨를 줄이거나 기능을 숨기지 않는다.

## 기능 보존 조건

SSH 연결·인증·재시도·복구·상태 판정, 저장과 미저장 초안, 설정 파일, 로그인 자동 시작, 단일 인스턴스 동작을 변경하지 않는다.

버튼과 메뉴의 의미·활성 조건·순서, Tab 이동, Enter/Escape, 모달 소유 관계와 취소 동작을 유지한다. 시각 검증을 위해 사용자의 실제 설정이나 연결을 변경하지 않는다.

## 사용자 결정

| 주제 | 선택 | 이유와 적용 범위 |
|---|---|---|
| 변경 성격 | 기능을 유지하고 외양만 개선 | 이름 라벨의 위쪽 정렬이 거슬리며, 화면 전체의 조화를 원함 |
| 적용 범위 | Windows 전체 화면 | 추가 이유는 제시하지 않음 |
| 디자인 방향 | 절제된 네이티브 정돈 | 현재 구조를 유지하며 정렬·배경·여백·글꼴 위계를 정리하는 선택 |
| 화면 검증 환경 | RDP 연결 유지, GDI 캡처 사용 | RDP만 가능한 환경에서도 검증해야 함 |

## Current Spec Impact

`docs/dev-plans/current-spec.md`에 **Windows 시각적 일관성** 요구사항을 추가한다.

추가할 의도는 라벨의 세로 중앙 정렬, 폼 배경 통일, 역할별 간격·크기 일관성, 네이티브 표현 유지, 고배율·좁은 창에서의 가독성이다. 기존 기능·배치 구조·플랫폼별 버튼 순서와 검증 공백은 그대로 유지한다. 문서 전체의 기존 한국어를 유지한다.

## 수용 기준

- 설정창과 규칙 편집창의 한 줄 라벨이 대응 입력 행 중앙에 놓이며, 회색 배경 조각이 사라진다.
- SSH 포트 라벨을 포함한 모든 라벨·입력·버튼에 겹침이 없다. 긴 내용도 기존 스크롤·편집 방식으로 확인할 수 있다.
- 설정·규칙·상태창의 간격과 버튼 높이가 일관되고, 트레이·About이 기존 OS 표현과 어울린다.
- 현재 실제 250% 배율과 자동 검증 대상 배율에서 글자·아이콘·포커스 표시를 식별할 수 있다.
- 동일 조건의 변경 전후 이미지로 개선을 확인하고, 자동 UI 회귀 검사로 기존 동작 보존을 확인한다.
- RDP 검증 구간에 새 그래픽 오류나 세션 단절이 발생하지 않는다. 캡처 성공과 입력 조작 검증 결과는 구분해 보고한다.
