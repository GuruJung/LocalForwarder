## Tracked Feature Spec

### 목적과 범위

앱 하나가 여러 호스트의 SSH 연결을 독립적으로 관리하는 트레이 프로그램으로 전환한다. 설정 창을 닫거나 개별 연결이 실패해도 앱은 계속 실행된다.

저장된 설정, 설정 창의 편집 내용, 실행에 사용한 설정, 사용자의 연결 의도를 구분한다. 연결 의도와 저장하지 않은 실행 설정은 현재 앱 실행 동안만 유지한다.

macOS를 기준으로 구현한다. Windows 구현과 전용 빌드·테스트 파일은 동결하고 기존 CI를 유지한다. 목적지 서비스의 주기적 상태 검사, 설치 프로그램, 자동 업데이트, 로그인 시 자동 실행은 추가하지 않는다.

### 시작과 앱 수명

- 설정 파일이 없거나 `--open-config`로 실행하면 설정 창을 먼저 연다. OK는 전체 연결 단계로, Cancel은 자동 연결 없이 일반 트레이 모드로 이어진다.
- 설정 파일이 있고 해당 옵션이 없으면 자동 연결 ON인 호스트들을 연결하고 트레이 모드로 운영한다. 호스트가 없는 설정도 허용한다.
- 손상되거나 지원하지 않는 설정은 보존하고 오류를 표시한다. 해당 설정으로 자동 연결하거나 덮어쓰지 않는다.
- 트레이 아이콘은 시작부터 유지한다. 개별 호스트의 연결 실패·단절은 다른 호스트와 앱 수명에 영향을 주지 않는다.
- 이미 실행 중이면 후속 실행은 기존 프로세스에 설정 열기를 요청한 뒤 종료한다. 설정 창이 이미 열렸으면 요청을 무시하고, 트레이 메뉴가 열렸으면 메뉴를 닫고 설정 창을 연다.
- 종료는 모든 연결 작업·예약을 취소하고 앱이 소유한 SSH 프로세스를 정리한다.

### 설정 화면과 저장

- 왼쪽에 새로 만들기, 호스트 목록, 미저장 표시를 둔다. 기존 호스트 삭제 기능을 유지한다.
- 오른쪽에 이름·SSH 접속 정보, 자동 연결, `ExitOnForwardFailure`, 연결 거부 시 재시도, 포워딩 편집 기능을 제공한다. 편집한 값으로 실행할 SSH 명령을 읽기 전용으로 표시한다.
- 설정 창을 새로 열 때 파일을 읽는다. 열린 창에서 호스트를 전환할 때는 메모리의 편집 내용을 유지한다. ‘호스트 설정’으로 이미 열린 창에 진입하면 재로드 없이 선택만 변경한다.
- 저장은 선택한 호스트만 반영한다. 다른 호스트의 미저장 변경을 저장하지 않으며, 현재 연결과 연결 의도도 바꾸지 않는다.
- 재연결은 선택한 호스트만 대상으로 한다. 미저장 변경이 있으면 ‘저장 후 재연결 / 저장 없이 재연결 / 취소’를 제공한다. 앞의 두 선택은 편집한 값으로 연결한다.
- 입력 검증과 필요한 저장이 성공한 뒤 기존 연결을 끊는다. 실패하면 기존 연결과 편집 내용을 유지한다.
- OK는 자동 저장하지 않는다. 미저장 변경이 있으면 ‘계속 편집 / 저장하지 않고 닫기’를 묻는다. Cancel과 창 닫기는 미저장 편집을 버리며, 이미 저장하거나 실행에 적용한 결과는 되돌리지 않는다.
- 운용 중 설정 창을 OK로 닫아도 전체 연결을 수행하지 않는다. 시작 단계의 설정 창에만 전체 연결 분기를 적용한다.
- 저장 없이 연결한 신규 호스트도 현재 실행 동안 관리한다. 트레이와 다시 연 설정 창에 임시 호스트로 표시하고, 앱 종료 시 소멸한다.
- 삭제는 확인 후 해당 호스트의 연결·예약·연결 의도와 저장 항목을 제거한다. 다른 호스트의 편집 내용을 저장하지 않는다.

### 연결 의도와 설정 적용

- 시작 시 자동 연결 ON인 호스트는 연결 의도 ON으로 초기화한다. 최초 연결에 실패해도 의도는 유지한다.
- 사용자 ‘연결·재연결’은 연결 의도를 ON으로, ‘끊기’는 OFF로 바꾼다. 자동 연결 설정은 변경하지 않는다.
- SSH 종료와 연결 실패는 연결 의도를 바꾸지 않는다.
- 저장만 하면 현재 연결은 유지하고 다음 연결부터 저장한 값을 적용한다.
- 저장 없이 재연결한 값은 임시 실행 설정으로 기억하여 수동 재연결과 자동 복구에도 사용한다. 편집 내용을 버려도 이미 적용한 임시 실행 설정은 유지한다.
- 해당 호스트를 명시적으로 저장하거나 전체 재연결을 수행하면 임시 실행 설정을 해제한다.
- 전체 재연결은 모든 현재 연결과 진행 중 작업을 정리하고, 저장된 자동 연결 ON 호스트들을 연결한다. 연결 의도도 이 기준으로 초기화한다. 자동 연결 OFF 호스트와 미저장 임시 호스트는 다시 연결하지 않는다.
- 호스트별 실패와 포트 충돌은 독립적으로 처리한다. 충돌을 해결하기 위해 다른 호스트의 연결을 강제로 끊지 않는다.

### 자동 복구와 제한된 재시도

- 절전·시스템 중단 복귀와 네트워크의 사용 불가→사용 가능 전환을 복구 계기로 삼는다. 일반적인 앱 포커스 복귀와 설정 창 열기는 제외한다.
- 관련 이벤트가 겹치면 하나로 합쳐 마지막 이벤트에서 5초 뒤 복구한다. 네트워크가 다시 끊기면 예약을 취소하고 다음 복구를 기다린다.
- 복구 시점에 연결 의도 ON이면서 실제로 disconnected인 호스트만 연결한다. 연결 유지 중이거나 연결 시도 중인 호스트는 건드리지 않는다.
- 대기 중 사용자의 수동 작업이 우선한다. 시작 설정을 Cancel하여 연결 의도가 없는 호스트는 자동 복구하지 않는다.
- 복구 시점 이후 늦게 감지한 단절은 추가 자동 복구하지 않는다. 사용자의 수동 연결 또는 이후 별도의 복구 이벤트를 기다린다.
- 재시도 옵션이 ON이면 연결 성립 전 명시적인 접속 거부 또는 서버의 조기 연결 종료·리셋에 한해 1초 뒤 한 번 더 시도한다.
- 인증·호스트 키 오류, 포트 충돌, 일반 타임아웃과 분류할 수 없는 실패는 재시도하지 않는다. 복구 실패 후 반복 재시도나 자동 종료도 하지 않는다.
- 기존 60초 자동 재연결·실패 후 종료 정책은 제거한다.

### 트레이와 포워딩 상태

- 포워딩을 표현하는 앱 아이콘과 메뉴 막대 아이콘을 제공한다.
- 툴팁은 프로그램 제목, 연결된 호스트 수, 연결 안 된 호스트 수를 표시한다. 연결됨에는 수동 연결한 자동 연결 OFF 호스트도 포함하고, 연결 안 됨에는 자동 연결 ON 호스트만 포함한다.
- 메뉴 순서는 ‘설정 / 전체 재연결 / 구분선 / 호스트별 하위 메뉴 / 구분선 / 종료’로 한다. 설정은 항상 사용할 수 있다.
- 호스트는 실제 연결 중이면 connected, 연결되지 않았고 자동 연결 ON이면 disconnected, OFF이면 disabled로 표시한다.
- connected에는 ‘재연결·끊기·호스트 설정’, 나머지에는 ‘연결·호스트 설정’을 제공한다. 작업 중 진행 상태를 표시하고 중복 실행을 막는다.
- 설정 화면에 편집 표와 별도의 읽기 전용 ‘현재 연결 상태’ 표를 둔다. 현재 실행에 사용한 규칙과 SSH 설정에서 상속된 규칙을 출처와 함께 표시한다.
- 규칙별 상태는 ‘준비 중 / 준비됨 / 개설 실패 / 연결 끊김 / 확인 불가’로 한다. 비활성 규칙은 편집 표에만 표시한다.
- SSH 연결과 포워딩 개설 결과를 분리한다. `ExitOnForwardFailure=OFF`에서는 일부 또는 전체 포워딩 실패가 있어도 살아 있는 SSH 연결을 connected로 표시하고 경고를 덧붙인다.
- 설정 화면과 트레이 하위 메뉴에 `SSH 연결됨 · 포워딩 준비 2 / 실패 1`처럼 요약한다. 확인 불가도 숨기지 않는다.
- SSH 종료 시 이전 ‘준비됨’을 해제하고 마지막 오류를 보존한다. 임시 실행 설정을 사용하는 경우 이를 명시한다.
- ‘준비됨’은 포워딩 개설 성공이며 목적지 서비스의 정상 동작을 보장하지 않는다. 실제 사용 중 관측한 목적지 연결 실패는 발생 시각과 함께 최근 오류로 남긴다.

### 호환성·인증·기본값

다음은 앞선 계획에서 정한 기본값이며, 별도의 사용자 개별 선택으로 기록하지 않는다.

- 새 호스트 옵션은 `autoConnect`, `exitOnForwardFailure`, `retryOnConnectionRefused`이며 모두 ON을 기본값으로 한다. 기존 설정을 읽을 때도 같은 기본값을 적용한다.
- 설정 버전은 2로 올린다. 버전 1은 읽을 수 있고 최초 저장 시 원본 백업을 보존한 뒤 버전 2로 저장한다. 읽기만 해서는 변환하지 않는다.
- 저장 위치, 손상 파일 보존, 원자적 저장과 사용자 전용 권한 정책을 유지한다.
- 동결된 Windows 앱과 구버전 앱은 버전 2 설정을 사용할 수 없다. 이 제한과 백업 복원 방법을 문서화한다. Windows 변경 예외는 이번 범위에 포함하지 않는다.
- 외부 터미널 인증 설정 기능을 유지하되, 명시적인 사용자 동작으로 선택한 호스트에만 수행한다. 앱 전체를 종료하거나 다른 호스트의 연결을 끊지 않는다.
- 인증 도우미의 무조건 재시도를 제거한다. 비밀번호·키 암호는 터미널에서만 입력하고, 기존 키 보존과 호스트 키 검증·서버 인증 정책을 유지한다.
- 인증 도우미 완료 후 해당 호스트의 저장 변경을 반영하고 다른 편집 내용을 보존한다. 연결은 사용자가 요청한다.

### Current Spec Impact

`replace`, `add`, `remove`를 적용한다. 현재 명세 전체의 설명 언어는 한국어로 유지하며 다음 의도를 정확히 갱신한다.

- **replace — 호스트와 규칙:** 인스턴스당 한 호스트·매번 선택을 단일 앱 다중 호스트 관리로, 모든 포워딩 실패의 일괄 실패를 옵션에 따른 처리로 변경한다.
- **replace — 저장:** 버전 1과 매 연결 전 즉시 저장 정책을 버전 2 호환성, 호스트별 저장, 편집·실행 설정 분리와 임시 실행 설정 정책으로 변경한다.
- **replace — 연결 수명:** 첫 실패의 무조건 재시도, 60초 복구·종료 정책을 연결 의도 기반 5초 복구와 조건부 1회 재시도로 변경한다.
- **replace — UI와 인증 복구:** 연결 성공 후 트레이 표시와 인증 복구 시 GUI 종료를 상시 트레이, 다중 호스트 메뉴, 앱을 유지하는 명시적 인증 복구로 변경한다.
- **add:** 시작 분기, 단일 인스턴스 요청 처리, 전체 재연결과 자동 복구의 차이, 규칙별 상태 표시 및 Windows 설정 호환성 제한을 추가한다.
- **remove:** 실패에 따른 앱 자동 종료와 과거 단절·종료 타이머 규칙을 현재 요구사항에서 제거한다.
- **preserve:** 시스템 OpenSSH 사용, 앱 규칙의 loopback 바인딩, 기존 SSH 규칙 존중, 비대화형 일반 연결, 보안·키 보존, 배포 범위와 Windows 동결 정책은 유지한다.

### 수용 기준

1. 시작의 모든 분기와 중복 실행에서 트레이·설정 창·SSH 프로세스가 중복 생성되지 않는다.
2. 여러 호스트의 연결·단절·실패가 독립적이고 개별 실패로 앱이 종료되지 않는다.
3. 호스트 전환과 저장·취소가 다른 호스트의 미저장 내용을 잃거나 저장하지 않는다.
4. 저장 없이 적용한 설정과 연결 의도가 수동 재연결·복구에 정확하게 반영된다.
5. 복구는 지정된 이벤트와 5초 대기를 따르며 정상 연결·수동 단절·늦은 단절을 임의로 재연결하지 않는다.
6. 조건부 1초 재시도 외에 숨은 반복 시도·자동 종료가 없다.
7. 포워딩 상태가 편집 내용과 실제 실행 내용을 혼동하지 않고 목적지 정상 여부를 과장하지 않는다.
8. 설정 변환·저장 실패·동시 도우미 저장에서 기존 데이터와 다른 호스트를 보존한다.
9. 종료·삭제·재연결 후 이전 프로세스와 타이머가 새 상태를 변경하거나 포트를 계속 점유하지 않는다.
10. Windows 동결 파일과 기존 검증을 보존하고, CI·실제 기기 검증·기능 동등성 상태를 구분하여 보고한다.
