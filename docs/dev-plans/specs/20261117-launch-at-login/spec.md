# Tracked Feature Spec

## 목표와 범위

macOS와 Windows의 트레이 메뉴에 체크 가능한 **로그인 자동 시작** 항목을 추가한다. 체크하면 현재 사용자의 로그인 자동 시작을 등록하고, 해제하면 해당 등록을 제거한다.

`main`에서 독립적으로 개발한다. 다른 세션의 설정창·규칙 모달·트레이 디자인 개선은 이번 변경에 포함하지 않는다.

## 요구사항

- 메뉴 순서는 **설정 → 로그인 자동 시작 → 전체 재연결 → 기존 나머지 항목**으로 한다.
- 최초 상태는 미등록이며, 앱 실행·업데이트만으로 자동 시작을 등록하지 않는다.
- 설정은 현재 컴퓨터의 현재 사용자에게만 적용한다. 호스트별 자동 연결 옵션과 분리하고 `config.json`에는 저장하지 않는다.
- 메뉴를 열 때 OS의 등록 상태를 다시 조회한다. 등록·해제 후에도 재조회한 결과로 체크 상태를 표시한다.
- 등록·해제는 현재 앱이나 SSH 연결을 종료·재시작하지 않는다. 실패하면 원인을 안내하고 성공한 것처럼 체크 상태를 바꾸지 않는다.
- 등록 처리 중에는 중복 클릭을 막는다. 상태 조회 실패는 명시적으로 표시하고 잘못된 상태를 근거로 설정을 변경하지 않는다.
- 로그인으로 실행되면 기존 일반 실행 정책을 따른다. 정상 설정이 있으면 설정창 없이 트레이로 시작하며 자동 연결 ON인 호스트만 연결한다. 설정이 없거나 손상됐으면 기존 설정창·오류 안내를 유지한다.
- 앱 종료와 자동 시작 해제는 별개다. 종료해도 등록을 유지하고, 체크 해제는 다음 로그인부터 적용한다.
- 관리자 권한, 시스템 서비스, 설치 프로그램, 유료 서명, 자동 업데이트는 추가하지 않는다.

### OS별 상태와 제한

- macOS에서 등록 후 시스템 승인이 필요하면 **로그인 자동 시작 (승인 필요)**로 표시한다. 등록된 상태임을 체크로 나타내되 실행 가능 상태로 오인하지 않도록 안내하고, 사용자가 선택하면 시스템 설정의 로그인 항목 화면을 연다. 체크 해제는 승인 대기 등록도 제거한다.
- Windows의 체크는 앱이 관리하는 자동 시작 등록 여부를 나타낸다. 작업 관리자·시스템 정책의 별도 차단을 강제로 해제하지 않는다.
- 앱은 사용자가 둔 위치에서 등록한다. 다른 위치로 자동 복사하거나 설치하지 않는다. 이동·삭제 후 자동 시작이 깨질 수 있음을 안내하고, 이동한 앱에서 체크 해제 후 다시 체크하면 현재 위치로 등록한다.
- 다른 앱의 자동 시작 항목은 수정하지 않는다. 자동 시작의 정확한 실행 시각은 OS에 따르며 즉시 실행을 보장하지 않는다.

## 사용자 결정

| 주제 | 선택 | 이유·범위 |
|---|---|---|
| 제공 방식 | 트레이의 체크 메뉴로 등록·해제 | 사용자가 직접 요청 |
| 플랫폼 | macOS와 Windows 모두 | 사용자가 직접 요청 |
| 작업 기준 | `main`에서 이 기능만 구현 | UI 개선은 다른 세션에서 진행 중 |
| 로그인 후 연결 | 기존 자동 연결 설정을 따름 | 추천안 선택, 별도 이유 미제시 |

기본 미등록, 현재 사용자 범위, 메뉴 위치와 앱 이동 시 재등록 방식은 이번 계획의 기본값이다.

## Current Spec Impact

현재 명세 전체의 한국어와 관련 없는 기존 의도를 유지한다.

- **replace:** “로그인 시 자동 실행은 포함하지 않는다”를 사용자 선택에 따른 로그인 자동 시작 지원으로 변경한다.
- **add:** 체크 메뉴, 사용자별 OS 등록, 승인 필요·실패 처리, 앱 이동 시 제한을 명시한다.
- **replace:** 트레이 메뉴 순서에 로그인 자동 시작을 추가한다.
- 기존 시작·자동 연결·설정 보존·단일 인스턴스·종료 정책은 유지한다.
- 다른 세션의 UI 기능 명세·계획·실행 상태는 수정하지 않는다.

## 수용 기준

1. 체크·해제 후 재실행해도 OS 등록 상태와 메뉴 표시가 일치한다.
2. 등록과 해제는 멱등적이며 다른 자동 시작 항목과 현재 SSH 연결에 영향을 주지 않는다.
3. 공백·한글 경로에서도 등록된 대상이 정확하고 테스트 옵션이나 `--open-config`가 포함되지 않는다.
4. 등록·조회·해제 실패 및 macOS 승인 필요 상태를 성공으로 오인하지 않는다.
5. 로그인 실행은 기존 자동 연결 정책을 그대로 사용하며 호스트 설정 형식은 바뀌지 않는다.
