## Tracked Feature Spec

### 요약과 요구사항

오래된 운영 문서와 구형 동작 지원을 제거한다. macOS와 Windows 모두 설정 v2만 지원하며, README는 **일반 앱 사용자와 직접 빌드·테스트하는 파워 유저**를 위한 영어 기본판과 한국어판으로 관리한다.

- `docs/verification/` 내 모든 파일과 `docs/dev-plans/*-catchup.md`를 삭제한다. 루트 `AGENTS.md`는 기존 개발 정책을 제거하고 원격 push 정책만 담도록 재작성한다.
- 승인된 구현 작업의 구현 브랜치는 별도 확인 없이 일반 push하여 CI를 실행한다. `implement-dev-plan`의 자동 push 금지 부분을 이 정책으로 대체하며, 원격 `main` push에는 항상 해당 작업에 대한 명시적 사용자 승인이 필요하다. 강제 push와 브랜치·worktree 삭제는 사전 승인하지 않는다.
- `legacy-v1` 전용 실행·테스트 경로와 v1 설정 읽기·백업·변환 기능을 제거한다.
- 지원하는 설정 버전은 `2`로 유지한다. 기존 v2의 선택 필드·기본값·입력 검증·원자적 저장·접근 권한은 유지한다.
- v1 또는 지원하지 않는 설정은 오류를 안내하고 자동 연결하거나 덮어쓰지 않는다. 사용자 홈에 이미 존재하는 설정·백업 파일은 삭제하지 않는다.
- `README.md`는 영어 기본판, `README_ko.md`는 한국어판으로 구성하고 상단에서 서로 연결한다. 두 문서의 기능 설명과 명령은 동등하게 유지한다.
- README 본문은 소개, 지원 환경, 다운로드·실행, 빠른 시작, 연결·트레이·자동 시작, 설정, 인증·문제 해결, 라이선스를 설명한다.
- README 마지막에는 파워 유저가 직접 빌드·테스트할 수 있도록 플랫폼별 필수 도구, 실행 위치, 명령과 결과물 위치를 간략히 제공한다. 필요한 권한이나 테스트 환경 조건도 실행에 필요한 수준으로 설명한다.
- README에는 AI Agent 지침, 동결·해제 이력, 개발 진행 상황과 미해결 개발 이슈를 넣지 않는다. 개발 현황은 `docs/dev-plans`로 연결한다.
- 양쪽 배포 패키지에 두 README를 포함한다.

### 사용자 결정

| 주제 | 선택과 이유 | 적용 범위 |
|---|---|---|
| 운영 문서 정리 | 검증·catchup 파일 삭제. 최초 AGENTS 삭제 요청은 후속 원격 push 정책 기록 요청으로 변경 | 지정된 추적 파일 |
| 원격 push | 다음부터 재확인하지 않도록 구현 브랜치 자동 push를 허용하고 스킬 지침을 오버라이드. main push는 항상 사용자 승인 필요 | AGENTS 지침·구현 및 CI 절차 |
| 구형 지원 | 되돌아갈 일이 없으므로 legacy 제거. 추가 확인에서 v2 설정만 지원하기로 선택 | 양쪽 앱·설정·테스트·안내 |
| README 언어 | 영어를 기본으로 하고 한국어판 별도 관리 | 루트 README 두 파일 |
| README 독자 | 일반 앱 사용자와 빌드·테스트까지 수행하는 파워 유저. AI Agent는 대상이 아님 | 내용과 구성 |
| 개발 안내 | 끝에 짧은 빌드·테스트 안내를 유지하고 개발 이슈는 dev-plans에서 확인 | 두 언어판 |

### Current Spec Impact

`docs/dev-plans/current-spec.md` 전체의 한국어 본문을 유지하며 다음을 반영한다.

- **replace:** v1/v2 읽기와 v1 백업·변환 계약을 v2 전용 지원 및 미지원 파일 보존으로 변경한다. 규칙 설명의 호환성 조항도 일치시킨다.
- **remove:** 동결·해제 이력, AGENTS 준수와 catchup 기록 의무, 삭제 문서 링크, legacy 평가 모드 설명을 제거한다.
- **add:** 일반 사용자·파워 유저를 위한 README 독자 및 언어 정책과 현재 동작만을 평가하는 검증 원칙을 추가한다.
- **retain:** 다중 호스트 동작, 보안, 저장 안전성, 양쪽 배포·검증 범위를 유지한다.
- **replace:** 삭제 문서에 남아 있는 유효한 미해결 사항·검증 공백은 현재 명세의 별도 상태 절로 압축한다. 특히 MAC-003 상태 판정 문제, 이름 NUL 처리 차이, 실기기 미검증 범위를 목표 동작과 구분한다. 이번 정리를 해당 문제의 해결로 기록하지 않는다.

기존 기능 명세는 역사적 결정 기록으로 보존한다. 삭제 파일을 현재 지침으로 참조하는 문장은 정리하고, 이전 v1 호환성 계약이 이번 명세로 대체됐음을 표시한다.

### 수용 기준과 제외 범위

- 지정 검증·catchup 문서와 구형 실행·변환 코드가 제거되고 남은 문서에 삭제 파일로 향하는 링크가 없다. AGENTS에는 구현 브랜치 자동 push 및 main push 승인 경계가 명시되어 있다.
- 두 플랫폼에서 v2 설정은 기존 의미로 동작하고 v1은 원본 바이트를 보존한 채 거부한다.
- 다중 호스트 및 인증·키 보존 검증이 유지된다. 구형 테스트 제거를 이유로 현재 기능 검증을 줄이지 않는다.
- README 두 언어판에서 일반 사용자는 설치·사용 방법을, 파워 유저는 빌드·테스트에 필요한 조건과 명령을 찾을 수 있다.
- 두 README의 정보가 일치하고 배포물에도 모두 포함된다.
- Git 이력, 기존 브랜치·worktree, 과거 기능 명세 전체 삭제와 미해결 제품 버그 수정은 이번 범위에 포함하지 않는다.
