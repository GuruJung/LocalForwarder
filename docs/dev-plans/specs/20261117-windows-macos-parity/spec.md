# Tracked Feature Spec

> 이 문서는 당시의 결정 기록이다. v1 설정 지원·이전·백업과 구형 실행·평가 동작에 관한 조항은 [저장소 정리 명세](../20261117-repository-cleanup/spec.md)로 대체됐다. 현재는 설정 v2와 현재 다중 호스트 동작만 지원하며 최신 의도는 [현재 명세](../../current-spec.md)를 따른다.

### 목표와 범위

현재 macOS 소스와 현재 기능 명세를 기준으로 Windows를 다중 호스트 트레이 앱으로 재구성한다. 사용자에게 보이는 기능·설정·연결 정책·화면 구성은 동일하게 맞추고, OS 통합과 외형은 Windows 네이티브 방식을 사용한다.

macOS 소스·리소스·빌드 설정·전용 테스트·전용 스크립트는 변경하지 않는다. Windows 구현, 공통 테스트, 공통 문서와 필요한 Windows CI 변경을 대상으로 한다. 명세와 macOS 구현이 충돌하거나 새로운 Windows 전용 정책 결정이 필요하면 사용자에게 확인한다.

Windows 11 x64·ARM64, 시스템 OpenSSH 9.5 이상, ZIP 배포를 유지한다. 이 버전 기준은 로컬 Windows 클라이언트에만 적용한다. SSH 자체 구현, 설치 프로그램, 자동 업데이트, 로그인 시 앱 자동 실행, 목적지 서비스의 주기적 검사는 추가하지 않는다.

### 기능 요구사항

| 영역 | 목표 동작 |
|---|---|
| 앱 수명 | 시작부터 트레이를 유지하고 여러 호스트를 독립 관리한다. 설정 닫기·연결 실패·단절로 종료하지 않는다. |
| 시작 | 설정 없음 또는 `--open-config`이면 설정창을 연다. 시작 설정의 OK는 저장된 자동 연결 ON 호스트 연결, Cancel은 연결 없는 트레이 모드로 진행한다. 정상 설정으로 일반 실행하면 자동 연결한다. |
| 중복 실행 | 같은 Windows 사용자·로그인 세션에서는 앱 하나만 실행한다. 후속 실행은 기존 앱에 설정 열기를 요청한다. 열린 설정·모달·미저장 편집을 재로드하거나 중복 생성하지 않는다. |
| 설정 편집 | 호스트별 편집과 미저장 표시를 유지한다. 선택 호스트 저장만 수행하며 다른 편집·현재 연결·연결 의도를 변경하지 않는다. |
| 연결 적용 | 미저장 연결은 저장 후 연결 / 저장 없이 연결 / 취소를 제공한다. 검증과 필요한 저장 성공 전에 기존 연결을 끊지 않는다. 임시 실행 설정·임시 호스트·전체 재연결의 의미는 현재 명세를 따른다. |
| 연결 의도 | 수동 연결은 ON, 끊기는 OFF로 바꾸며 저장된 자동 연결 옵션과 분리한다. 실패·SSH 종료는 의도를 바꾸지 않는다. |
| 자동 복구 | 절전 복귀와 네트워크 사용 불가→가능 전환을 마지막 이벤트부터 5초로 병합한다. 의도 ON인 disconnected 호스트만 복구한다. 수동 작업 우선, 재단절 취소, 늦게 감지한 단절 제외를 유지한다. |
| 제한 재시도 | 옵션 ON인 연결 성립 전 접속 거부·조기 종료·리셋만 1초 후 한 번 재시도한다. 인증·호스트 키·포트 충돌·타임아웃·미분류 오류는 제외한다. 기존 60초 재연결·자동 종료는 제거한다. |
| 실행 상태 | SSH 연결과 규칙별 개설 결과를 분리한다. 앱 규칙과 상속 규칙의 출처·상태·최근 오류·발생 시각을 표시한다. 불확실한 결과는 확인 불가로 표시하고 종료 후 준비됨을 해제한다. |
| 인증 준비 | 명시적 선택 호스트에만 외부 터미널 도우미를 실행한다. 앱과 다른 연결·편집을 유지하고 완료 후 자동 연결하지 않는다. 기존 키·제한 옵션·호스트 키 검증을 보존한다. |

세부 저장·삭제·OK/Cancel·트레이 메뉴·상태 표시의 의미는 현재 명세의 해당 요구사항을 모두 수용 기준으로 적용한다. 활성 포워딩 규칙이 없는 호스트도 최신 macOS처럼 허용한다.

### UI와 Windows 전용 정책

- 좌측 상단의 새로 만들기·삭제, 호스트 목록·미저장 표시, 우측 SSH 설정·세 옵션·포워딩 편집·명령 프리뷰를 동일하게 구성한다.
- 사용자명·포트, 개인키·파일 선택을 각각 한 행에 배치한다. OK/Cancel은 양쪽 패널 밖 하단에 고정한다.
- 인증 설정 오른쪽의 `연결 상태…` 버튼으로 선택 호스트에 고정된 모달을 연다. 실시간 상태 갱신, Escape로 닫기, 편집 보존, 신규·미연결 호스트 조회를 지원한다.
- Windows DPI와 창 크기에 맞게 배치하며 최소 크기에서 입력·버튼이 겹치지 않게 한다. 긴 오류와 많은 규칙은 스크롤로 확인한다.
- 중복 포트는 한 호스트 내부의 활성 규칙만 사전 차단한다. 다른 호스트·외부 프로그램과의 충돌은 SSH 결과를 따르고 기존 연결을 끊지 않는다. Windows 중복 바인딩의 전달 대상 불확실성은 문서에 안내한다.
- IPv4/IPv6 내부망 또는 인터넷 연결을 네트워크 사용 가능으로 판단한다. Google 등 외부 사이트를 앱이 직접 검사하지 않는다. 최초 통지와 사용 가능 상태가 유지되는 단순 변경은 복구 계기로 삼지 않는다.
- ssh-agent가 준비되지 않았다면 설정 방법을 안내한다. **관리자 설정 버튼·UAC 요청·서비스 설정 변경은 구현하지 않는다.** 사용자 설정 후 인증 도우미를 다시 실행한다.
- OpenSSH Client가 없거나 9.5 미만이면 설치·업데이트 방법을 안내하고 앱·설정을 유지한다. 앱이 자동 설치하거나 관리자 설정을 변경하지 않는다. Windows의 `-E` 파일 공유·파이프 쓰기 제약 때문에 대상 프로세스의 PID가 포함된 진단 로그를 사용하여 ProxyJump 로그와 구분한다.
- 로그인 세션별 앱은 독립 실행하되, 같은 사용자 설정의 동시 변경은 세션을 가로지르는 파일 잠금으로 보호한다.

### 설정·공개 인터페이스

- 실제 사용자 홈의 `.LocalForwarder/config.json`을 유지한다.
- v1·v2를 읽고 v2로 저장한다. `autoConnect`, `exitOnForwardFailure`, `retryOnConnectionRefused`는 macOS와 같은 기본값과 누락/null 처리 기준을 적용한다.
- v1 읽기만으로 변경하지 않는다. 최초 변경 전 원본 바이트를 고유 백업에 보존하고, 백업 실패 시 원본 교체를 중단한다.
- 잠금 안에서 최신 파일을 읽고 선택 호스트만 원자적으로 변경한다. 인증 도우미는 최신 호스트의 개인키 필드만 변경한다.
- macOS와 같은 입력 검증을 적용한다. 기존 Windows에서만 허용되던 입력은 임의 정규화하거나 덮어쓰지 않고 문제 항목을 안내한다. UI의 빈 선택 입력은 미지정으로 저장한다.
- 사용자 전용 접근 권한, 손상·지원 불가 파일 보존, 저장 실패 시 기존 데이터와 연결 보존을 유지한다.
- Windows에 `--open-config`를 추가하고 기존 `--setup-auth PROFILE_ID`를 유지한다. 별도 설정 버전이나 Windows 전용 JSON 옵션은 추가하지 않는다.

|---|---|---|
| 기준과 변경 범위 | 최신 macOS를 분석하여 Windows를 맞추고 macOS는 변경하지 않음 | macOS가 최신이라는 사용자 설명 |
| UI | 같은 구성·Windows 네이티브 | 별도 이유 미제시 |
| 중복 포트 | macOS와 동일한 앱 정책 | Windows 차이 설명 후 선택, 별도 이유 미제시 |
| 입력 검증 | macOS 기준으로 통일 | 별도 이유 미제시 |
| 네트워크 복구 | 내부망 복구도 포함 | 내부망·인터넷 차이 설명 후 선택 |
| Windows OpenSSH 버전 | 로컬 클라이언트 9.5 이상 | 네이티브 CI에서 확인한 로그 출력 제약 설명 후 사용자가 명시적으로 선택. 원격 서버에는 이 최소 버전을 요구하지 않음 |
| 목적지 오류 진단 | 실제 SSH 오류만 표시 | Windows 테스트 서버가 닫힌 목적지 연결을 오류 진단 없이 종료하는 사례 설명 후 선택. 포워딩 개설 상태를 유지하며 오류 추측·별도 서비스 검사는 하지 않음 |
| ssh-agent | 설정 방법만 안내 | 앞선 관리자 설정·자동 시작 선택을 대체함. 변경 이유 미제시 |
| 단일 인스턴스 | 사용자·로그인 세션마다 하나 | 별도 이유 미제시 |
| 구현 완료 기준 | CI와 독립 리뷰 완료, 실기기 확인은 별도 | 실기기 미검증 범위와 확인 절차를 남김 |

### Current Spec Impact

`docs/dev-plans/current-spec.md` 전체의 한국어와 기존 공통 의도를 유지하며 다음을 반영한다.

- **replace:** Windows v1·다중 호스트 미구현 설명을 새 구현 상태로 갱신한다. 실제 검증 결과와 남은 검증 공백을 구분한다.
- **replace:** 최신 설정창 배치와 연결 상태 모달의 macOS 한정 범위를 양쪽 플랫폼의 공통 사용자 동작으로 확장한다.
- **replace:** 현재 Windows가 v2를 읽지 못한다는 설명을 구버전 Windows·구버전 앱의 제한으로 변경한다.
- **replace:** Windows 평가의 `legacy-v1` 기준을 `multi-host-v2`로 전환한다.
- **add:** Windows의 로그인 세션별 인스턴스, 내부망 포함 네트워크 복구 기준, OpenSSH·ssh-agent 준비 안내 정책을 명시한다.
- 구현 완료·자동 검증 완료·실기기 미검증을 구분한다. 현재 구현 차이와 검증 공백은 [현재 명세](../../current-spec.md)에서 확인한다.

### 수용 기준

1. macOS 보호 범위에 변경이 없고 Windows 두 아키텍처에서 빌드·패키징된다.
2. 다중 호스트의 연결·편집·저장·삭제·복구가 독립적이며 기존 연결과 다른 호스트 데이터를 부당하게 변경하지 않는다.
3. 상태 표시가 실제 실행 설정과 진단 근거를 반영하고 ProxyJump의 성공을 대상 서버 성공으로 오인하지 않는다.
4. v1 백업·v2 저장·동시 변경·실패 복구에서 데이터 손실이 없고 손상 파일을 보존한다.
5. 삭제·재연결·종료가 소유한 SSH·조회 자식과 예약 작업을 정리하고 이전 콜백이 새 상태를 변경하지 않는다.
6. Windows 전용 정책이 위 사용자 결정과 일치한다. 검증 제외를 기능 동등성의 증거로 사용하지 않는다.
