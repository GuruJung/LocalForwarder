# LocalForwarder 현재 기능 명세

이 문서는 다중 호스트 트레이 앱의 현재 제품 의도를 다룬다. 설정창·규칙 모달·트레이 표시와 호스트 설명은 [설정창·트레이 개선 명세](specs/20261117-settings-tray-refinement/spec.md)를 따른다. Windows 동등화 범위와 플랫폼별 결정은 [Windows 기능 동등화 명세](specs/20261117-windows-macos-parity/spec.md)를 따른다. 결정 배경과 수용 기준은 [다중 호스트 기능 명세](specs/20261115-multi-host-tray/spec.md)에, 이전 동작은 [v1 기능 명세](specs/20261111-localforwarder-v1/spec.md)에 기록한다.

## 플랫폼별 개발 상태

- 2026-11-17 사용자 요청으로 Windows 동결과 macOS 우선 개발 제한을 해제했다. macOS·Windows 양쪽의 소스·빌드·리소스·테스트·스크립트·CI를 플랫폼별 제한 없이 수정할 수 있다.
- 양쪽 빌드·테스트·패키징 CI를 유지하고 구현 변경에 맞게 갱신한다. 아래 공통 동작은 목표 명세이며, 실제 구현과의 차이는 [Windows 반영 대기](windows-catchup.md)와 [macOS 반영 대기·차이 기록](macos-catchup.md)에 기록한다.
- CI 통과, 실제 기기 수동 검증, 플랫폼 기능 동등성을 구분한다. macOS 신규 동작의 테스트를 Windows에서 제외하는 것은 기능 동등성의 증거가 아니다.
- 이전 차이 기록의 근거와 미검증 상태를 보존하며, 개발 정책은 [AGENTS.md](../../AGENTS.md)를 따른다. 정책 해제만으로 구현·검증 완료로 처리하지 않는다.

## 제품과 배포

- 시스템 OpenSSH를 실행하는 작은 네이티브 GUI이며 SSH 프로토콜을 직접 구현하지 않는다. Windows 로컬 클라이언트는 OpenSSH 9.5 이상을 사용하며 구버전에는 업데이트 방법만 안내한다. 원격 서버에 같은 최소 버전을 요구하지 않는다.
- macOS 15 이상 Apple Silicon과 Windows 11 x64·ARM64 배포를 유지한다. Windows도 다중 호스트·설정 v2를 지원한다. 배포 및 검증 상태는 플랫폼별 반영 기록에서 구분한다.
- GuruJung/LocalForwarder 공개 저장소에서 MIT 라이선스로 배포한다. GitHub 네이티브 러너로 CPU별 ZIP을 만든다.
- macOS는 ad-hoc 서명하며 유료 인증서 서명·공증, 설치 프로그램, 자동 업데이트는 포함하지 않는다. 로그인 시 자동 실행은 사용자의 명시적인 선택으로 지원한다.

## 시작과 앱 수명

- 앱 하나가 여러 호스트를 독립적으로 관리하고 시작부터 트레이 아이콘을 유지한다. 설정 창 닫기와 개별 연결 실패·단절은 앱을 종료하지 않는다.
- 설정 파일이 없거나 `--open-config`로 실행하면 설정 창을 먼저 연다. OK는 자동 연결 ON 호스트의 전체 연결 단계로, Cancel은 자동 연결 없는 트레이 모드로 이어진다. 호스트가 없는 설정도 허용한다.
- 설정 파일이 있고 해당 옵션이 없으면 자동 연결 ON 호스트들을 연결한다. 손상되거나 지원하지 않는 설정은 보존하고 오류를 표시하며 자동 연결·덮어쓰기를 하지 않는다.
- Windows 단일 인스턴스 범위는 같은 사용자·로그인 세션이다. 서로 다른 로그인 세션은 독립 트레이를 사용하고, 공유 설정은 세션 간 파일 잠금으로 보호한다.
- 후속 실행은 기존 프로세스에 설정 열기를 요청하고 종료한다. 이미 열린 설정 창은 재로드하지 않는다. 트레이 메뉴가 열렸으면 닫고 설정 창을 연다.
- 종료는 모든 호스트의 작업·예약을 취소하고 앱이 소유한 SSH 및 설정 조회 자식 프로세스를 정리한다.

## 호스트와 포워딩

- SSH 별칭 또는 주소와 선택적 사용자명·포트·개인키 경로를 사용하며 미지정 값은 SSH 설정을 따른다. 일반 연결은 비대화형이다.
- 앱의 활성 규칙은 `127.0.0.1`에 바인딩한다. 기존 SSH 설정의 `LocalForward`, `RemoteForward`, `DynamicForward`는 원래 바인딩 범위대로 존중하고 읽기 전용으로 표시한다.
- 호스트 이름의 공백뿐인 값, 명시적 빈 접속 선택 필드, SSH 토큰의 Unicode 공백·제어문자는 macOS와 같은 기준으로 거부한다. UI의 빈 선택 입력은 미지정으로 저장하며, 거부된 기존 파일을 임의 변환하지 않는다.
- 명백한 입력 오류는 연결 전에 검증한다. 실제 포트 점유·호스트 중복은 미리 검사하지 않고 SSH 결과를 따른다. 충돌 해결을 위해 다른 호스트를 끊지 않는다.
- 한 호스트의 활성 규칙 사이에 중복 로컬 포트가 있으면 입력 오류로 처리한다. Windows OpenSSH가 호스트 간 중복 바인딩을 허용하더라도 앱은 SSH 결과를 따르며, 중복 포트의 전달 대상을 보장하지 않는다.
- `ExitOnForwardFailure=ON`이면 개설 실패를 연결 실패로 처리한다. OFF이면 일부 또는 전체 포워딩 실패가 있어도 살아 있는 SSH는 connected이며 경고를 표시한다.
- 실행에 사용한 활성 규칙과 상속 규칙을 출처와 함께 별도 ‘현재 연결 상태’ 표에 표시한다. 상태는 준비 중·준비됨·개설 실패·연결 끊김·확인 불가다. 비활성 규칙은 편집 표와 트레이 목록에서 별도 비활성 상태로 표시한다.
- SSH와 포워딩 상태를 분리하여 `SSH 연결됨 · 포워딩 준비 2 / 실패 1`처럼 요약한다. 확인 불가도 표시한다. 종료 시 이전 준비됨을 해제하고 마지막 오류를 보존한다.
- 준비됨은 포워딩 개설 성공이며 목적지 서비스 정상 여부가 아니다. 서비스의 주기적 검사는 하지 않는다. 실제 사용 중 관측한 목적지 오류는 발생 시각과 함께 남긴다.
- Windows SSH 서버가 목적지 연결 실패 시 오류 진단 없이 채널만 종료하는 경우, 개설된 포워딩 상태를 유지하고 오류를 추측해 추가하지 않는다. 최근 오류는 실제 SSH 오류 진단만 표시한다.
- 연결·포워딩 준비 판정은 실제 대상 SSH 프로세스가 생성한 상태 메시지를 근거로 한다. 서버 배너·소프트웨어 식별자·목적지 오류 설명에 포함된 문자열을 인증 성공이나 규칙 개설 결과로 해석하지 않는다. macOS의 문자열 판정 보강은 [MAC-003](macos-catchup.md#mac-003-서버가-제공한-로그-문자열과-상태-판정-분리)에 기록한다.

## 편집과 저장

- 실제 사용자 홈의 `.LocalForwarder/config.json`을 사용한다. 버전 2를 저장하며 v1은 읽을 수 있다. 새 호스트의 `autoConnect`, `exitOnForwardFailure`, `retryOnConnectionRefused`는 모두 ON이고, 기존 설정에 필드가 없어도 같은 기본값이다.
- v1을 읽기만 해서는 변환하지 않는다. 최초 저장 전에 원본 바이트를 `config-v1-<고유 ID>.json`에 보존한 뒤 v2로 저장한다. v1 기반 구버전 Windows·구버전 앱은 v2를 사용할 수 없다.
- 저장은 잠금 안에서 최신 파일을 읽고 선택 호스트만 수정하여 원자적으로 교체한다. 사용자 전용 권한과 손상 파일 보존을 유지한다. 같은 항목은 마지막 저장을 따르며 도우미의 개인키 변경도 최신 호스트에만 적용한다.
- 호스트의 선택 문자열 `description`은 설명용이며 SSH 인수·인증 정보에 사용하지 않는다. 누락/null/빈 문자열은 설명 없음이고 빈 값은 저장 시 생략한다. 한 줄 텍스트로 개행과 NUL을 거부한다. 설명은 선택 저장·초안·인증 키 갱신에서 보존하고, 설명만의 차이로 실행 연결 설정 차이를 표시하지 않는다. 구버전 앱에서 다시 저장하면 설명이 유실될 수 있다.
- 양쪽 설정창의 기본 클라이언트 크기는 약 900×650 논리 단위다. 시스템 글꼴 크기를 유지하고 작업 영역에 맞게 줄이며 작은 화면에서는 설정 폼을 스크롤한다. 이름·설명 (선택)·SSH 별칭/주소 순서로 배치한다.
- 양쪽 플랫폼의 설정 창은 일반 너비에서 왼쪽 상단에 새로 만들기·호스트 삭제를 같은 행으로 배치하고, 그 아래에 호스트 목록과 미저장 표시를 제공한다. 오른쪽에는 SSH 설정·세 옵션·포워딩 편집·읽기 전용 실행 명령 프리뷰를 제공한다.
- 일반 너비에서는 사용자명·SSH 포트를 한 행에, 개인키 입력·파일 선택 버튼을 한 행에 배치한다. 화면 작업 영역이 좁으면 입력과 버튼을 여러 행으로 재배치하고 설정 폼을 스크롤하여 접근한다. Windows는 사이드바 폭을 줄이고, macOS는 매우 좁은 창에서 호스트 영역을 폼 위에 배치한다. 설정 폼은 가용 너비를 채우며 입력과 버튼이 겹치거나 잘리지 않는다.
- 확인·취소 버튼은 양쪽 패널 바깥의 창 하단 고정 영역에 오른쪽 정렬하며 폼 스크롤과 관계없이 보인다. 설정창과 규칙 팝업의 버튼은 왼쪽부터 Windows는 확인·취소, macOS는 취소·확인 순서다. 선택 호스트 저장·연결·인증 버튼은 설정 폼에 둔다. [macOS 설정창 배치 결정](specs/20261116-macos-settings-layout/spec.md)을 따른다.
- 포워딩은 `새 규칙…`·`규칙 편집…` 또는 선택 행 더블클릭으로 여는 모달에서 사용 여부·로컬 포트·목적지 호스트·포트를 편집한다. 목록에는 사용 체크박스와 `규칙 삭제`를 유지한다. 신규 기본값은 활성 `8080 → localhost:80`이다. 확인 후에만 규칙을 초안에 반영하고 편집 시 ID·순서를 보존한다. 취소·Escape·닫기는 모달 변경만 버린다. 확인은 파일 저장이나 연결을 하지 않는다.
- 규칙 모달은 부모 설정창과 호스트 전환을 차단하며 중복 실행은 기존 모달을 앞으로 가져온다. 포트·목적지·활성 규칙의 중복 포트를 검증하되 아직 호스트 이름·주소가 없는 초안에서도 규칙을 작성할 수 있다.
- 설정 폼에 상시 상태·검증 메시지 위젯을 두지 않는다. 저장 성공은 미저장 표시 해제로 알리고 성공 팝업을 띄우지 않는다. 사용자 작업 실패는 경고 대화상자로, 규칙 입력 오류도 규칙 모달 소유의 경고 대화상자로 알린다. 규칙 모달에 상시 오류 표시 영역을 두지 않으며 오류 발생 시 편집창과 입력값을 유지한다. 비동기 SSH 오류는 연결 상태 팝업에서 조회하며 변화마다 경고를 띄우지 않는다.
- 현재 연결 상태는 설정 폼 안에 중복 표시하지 않고, 인증 설정 오른쪽의 `연결 상태…` 버튼으로 여는 모달 팝업에 표시한다. 팝업을 열 때 선택한 호스트의 이름·SSH 대상, 상태 요약·오류·실행 설정 안내·포워드별 상태·준비됨 안내를 실시간으로 갱신한다. 편집값의 SSH 명령 프리뷰는 설정 창에 유지한다.
- 상태 팝업이 열려 있으면 설정 편집과 다른 호스트로의 선택 변경을 막는다. 닫기·Escape는 팝업만 닫고 미저장 편집을 보존한다. 신규·미연결 호스트도 조회할 수 있고 열기·닫기로 저장·연결·재연결·자동 복구를 실행하지 않는다. [macOS 연결 상태 팝업 결정](specs/20261116-macos-connection-status-dialog/spec.md)을 따른다.
- 창을 새로 열면 파일을 읽는다. 열린 창의 호스트 전환과 ‘호스트 설정’ 진입은 편집 내용을 보존하고 선택만 바꾼다.
- 저장은 선택 호스트만 반영하며 다른 미저장 호스트·현재 연결·연결 의도를 바꾸지 않는다. 재연결은 미저장 상태에 따라 저장 후 재연결 / 저장 없이 재연결 / 취소를 제공한다.
- 검증과 필요한 저장이 성공한 뒤 기존 연결을 끊는다. 실패하면 기존 연결과 편집 내용을 유지한다.
- OK는 자동 저장하지 않는다. 미저장이 있으면 계속 편집 / 저장하지 않고 닫기를 묻는다. Cancel과 닫기는 미저장 편집만 버리며 이미 저장·실행한 결과를 되돌리지 않는다. 운용 중 OK는 전체 연결을 하지 않는다.
- 저장 없이 연결한 신규 호스트는 현재 실행의 임시 호스트로 트레이와 다시 연 설정 창에 나타나며 앱 종료 시 소멸한다.
- 삭제는 확인 뒤 해당 호스트의 연결·예약·의도와 저장 항목만 제거한다.

## 연결 의도와 설정 적용

- 시작 전체 연결은 자동 연결 ON인 저장 호스트의 의도를 ON으로 초기화한다. 최초 연결 실패와 SSH 종료는 의도를 바꾸지 않는다.
- 사용자의 연결·재연결은 의도를 ON으로, 끊기는 OFF로 바꾸며 저장된 자동 연결 옵션은 바꾸지 않는다.
- 저장만 하면 현재 연결을 유지하고 다음 연결부터 저장값을 사용한다. 임시 실행 설정이 없다면 수동 연결은 최신 저장값을 읽는다.
- 저장 없이 재연결한 값은 임시 실행 설정으로 기억하여 수동 재연결·자동 복구에도 사용한다. 편집 취소는 이미 적용한 실행 설정에 영향을 주지 않는다.
- 해당 호스트 명시적 저장 또는 전체 재연결은 임시 실행 설정을 해제한다.
- 전체 재연결은 현재 연결과 작업을 모두 정리하고 저장된 자동 연결 ON 호스트만 연결하며 의도도 이 기준으로 초기화한다. 자동 연결 OFF와 미저장 임시 호스트는 다시 연결하지 않는다.

## 로그인 자동 시작

- 트레이의 `로그인 자동 시작` 체크 메뉴로 현재 사용자·현재 컴퓨터의 OS 등록을 추가하거나 제거한다. 최초에는 미등록이며 앱 실행·업데이트만으로 등록하거나 복원하지 않는다. 호스트별 자동 연결 옵션과 별개이며 `config.json`에 저장하지 않는다. [로그인 자동 시작 명세](specs/20261117-launch-at-login/spec.md)를 따른다.
- 메뉴를 열 때와 등록·해제 후 OS 상태를 다시 조회한다. 처리 중에는 중복 클릭을 막고, 조회 실패 시 상태 확인 실패를 표시하여 잘못된 상태로 설정을 바꾸지 않는다. 실패를 성공한 체크 상태로 표시하지 않는다.
- macOS는 앱 자체의 로그인 항목을 사용한다. OS에 등록 기록이 없는 상태는 체크 해제된 `로그인 자동 시작 (등록 필요)`로 구분하여 사용자가 등록할 수 있다. 승인 대기 등록은 체크된 `로그인 자동 시작 (승인 필요)`로 구분하고 사용자가 선택하면 시스템 설정의 로그인 항목 화면을 연다. 체크 해제는 승인 대기 등록도 제거한다.
- Windows는 현재 사용자 Run 등록을 사용한다. 체크는 앱이 관리하는 등록 여부이며 작업 관리자·시스템 정책의 별도 차단을 강제로 해제하지 않는다. 다른 앱의 항목이나 시스템 서비스는 변경하지 않는다.
- 로그인 실행은 기존 일반 실행 정책을 따른다. 정상 설정이면 설정창 없이 트레이에서 자동 연결 ON인 호스트만 연결하며, 설정 없음·손상 시 기존 설정창·안내를 유지한다. 등록 대상에 테스트 옵션이나 `--open-config`를 넣지 않는다.
- 등록·해제는 현재 앱과 SSH 연결에 영향을 주지 않는다. 앱 종료는 등록을 유지하고 체크 해제는 다음 로그인부터 적용된다. 실행 시점은 OS에 따르며 즉시 실행을 보장하지 않는다.
- 앱은 현재 위치에서 등록하며 자동 복사·설치하지 않는다. 이동·삭제 후에는 자동 시작이 깨질 수 있으며 이동한 앱에서 체크 해제 후 다시 체크하여 현재 위치를 등록한다. 관리자 권한·유료 서명·자동 업데이트를 추가하지 않는다.

## 자동 복구와 제한된 재시도

- 절전·시스템 중단 복귀와 네트워크 사용 불가→사용 가능 전환만 복구 계기다. 최초 네트워크 상태 통지·일반 포커스 복귀·설정 창 열기는 복구 계기가 아니다.
- Windows에서는 IPv4/IPv6 내부망 또는 인터넷 연결을 사용 가능으로 판단한다. 외부 사이트를 앱이 직접 검사하지 않으며, 최초 통지와 사용 가능 상태가 유지되는 단순 변경은 복구 계기가 아니다.
- 겹친 이벤트는 마지막 이벤트부터 5초 뒤 한 번 복구한다. 네트워크가 다시 끊기면 예약을 취소한다.
- 복구 시 의도 ON이면서 실제 disconnected인 호스트만 연결한다. 정상 연결·연결 중·수동 단절·시작 Cancel로 의도 없는 호스트는 건드리지 않는다. 대기 중 사용자 수동 작업이 우선한다.
- 복구 시점 후 늦게 감지한 단절은 추가 자동 복구하지 않는다. 수동 연결 또는 이후 별도 복구 이벤트를 기다린다.
- 재시도 옵션 ON일 때 연결 성립 전 명시적인 접속 거부·서버 조기 종료·리셋에 한해서 1초 뒤 한 번 더 시도한다.
- 인증·호스트 키 오류, 포트 충돌, 일반 타임아웃과 분류 불가 실패는 재시도하지 않는다. 복구 실패 후 반복 재시도·자동 종료·기존 60초 정책은 없다.

## 트레이와 인증 준비

- 포워딩을 표현하는 앱·메뉴 막대 아이콘을 제공한다. 메뉴 순서는 설정 / 로그인 자동 시작 / 전체 재연결 / 구분선 / 호스트별 하위 메뉴 / 구분선 / 종료다. 설정은 항상 사용할 수 있다.
- 호스트 메뉴는 상태 아이콘과 이름을 사용하며 connected/disconnected/disabled 문자열을 붙이지 않는다. 호스트 아이콘은 SSH 연결됨(`connected`), 미연결 자동 연결 ON(`disconnected`), 미연결 자동 연결 OFF(`disabled`) 세 상태만 색과 모양으로 구분한다. SSH가 연결되면 개별 포워딩 실패와 무관하게 연결됨 아이콘을 사용한다. 작업 중·임시 실행 여부는 텍스트로 표시하되 포워딩 경고 문구를 붙이지 않는다. 포워딩 문제는 서브메뉴의 개별 규칙 상태 아이콘으로 표시한다. 연결됨에는 재연결·끊기·호스트 설정, 나머지에는 연결·호스트 설정을 제공하고 진행 중 중복 작업을 막는다. 설정·전체 재연결·종료와 호스트 동작에도 기능 아이콘을 제공한다.
- 호스트 하위 메뉴는 클릭 불가능한 SSH·포워딩 요약 / 구분선 / 규칙별 정보·상태 아이콘 / 구분선 / 기존 연결 동작 순서다. 부가 오류·실행 설정 안내 행은 두지 않고 상세는 연결 상태 팝업에 유지한다.
- 트레이 규칙은 현재·마지막 실행 설정의 앱 규칙(비활성 포함)과 관측한 SSH 상속 규칙을 출처와 함께 표시한다. 실행 이력이 없으면 저장된 앱 규칙을 사용하고 활성 규칙은 미연결로 표시한다. 미저장 초안이나 이후 저장값을 실행 규칙과 혼합하지 않는다. 비활성은 별도 아이콘으로 구분하고 규칙이 없으면 `포워딩 규칙 없음`을 표시한다. 규칙 행은 조회용이다.
- 열린 메뉴의 상태 갱신은 메뉴를 닫거나 선택 위치를 불필요하게 초기화하지 않는다. 메뉴 표시를 위한 SSH 조회·목적지 검사를 추가하지 않는다.
- 트레이 아이콘 툴팁은 제목·연결 수·미연결 수를 표시한다. 연결 수에는 수동 연결한 자동 연결 OFF도, 미연결 수에는 자동 연결 ON만 포함한다.
- macOS 호스트 메뉴 행에는 툴팁을 표시하지 않는다. 호스트·규칙 상태는 서브메뉴에서, 오류 상세와 실행 설정 차이는 연결 상태 팝업에서 확인한다.
- Windows OpenSSH Client가 없거나 9.5 미만이거나 암호화된 키 사용에 필요한 ssh-agent가 준비되지 않았으면 설치·업데이트·설정 방법을 안내한다. 앱은 OpenSSH 설치, 관리자 권한 요청, 서비스 설정 변경을 하지 않는다.
- 외부 터미널 인증 도우미는 명시적으로 선택한 호스트에만 실행하며 앱과 다른 연결을 유지한다. 인증 도우미의 무조건 재시도는 없다.
- 기존 키를 우선 사용하고 필요한 새 키는 암호 없이 생성한다. 비밀번호·키 암호는 터미널에서만 입력한다. 일반 Linux/macOS 계정의 공개키 등록은 기존 키·제한 옵션을 보존하고 중복하지 않는다. 호스트 키 검증·서버 인증 정책을 우회하지 않는다.
- 도우미 완료 후 해당 호스트 저장 변경만 반영하고 다른 편집을 보존한다. 연결은 사용자가 요청한다.
- 유휴 상태는 이벤트와 일회성 타이머로 대기한다. 배포 크기와 실제 유휴 CPU·메모리를 보고하며 임의 수치 목표는 두지 않는다.

## 검증 범위

- 양쪽 플랫폼 평가는 `--behavior multi-host-v2`로 실제 production 연결 관리자의 다중 호스트·설정·복구·정리 동작을 검사한다. 기본 `legacy-v1`은 구버전 시나리오 재현용이며 현재 Windows 기능 동등성 평가로 사용하지 않는다.
- Windows 네이티브 sshd로 대체할 수 없는 Windows 클라이언트→Linux/macOS 서버의 실제 인증 등록은 별도 검증한다. Windows GUI·DPI·외부 터미널·절전·물리 네트워크·VPN 전환의 수동 확인 절차는 [Windows 검증 안내](../verification/windows-parity.md)에 둔다.
- headless 검증과 네이티브 UI, 실제 절전·네트워크 전환의 수동 검증은 별개다. 수행하지 않은 macOS·Windows 실기기 검증을 완료로 기록하지 않는다.
