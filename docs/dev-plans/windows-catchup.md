## 상태와 기준

- 2026-11-13: 사용자 요청으로 macOS 동결을 해제하고 Windows 구현을 동결했다. 주말 동안 macOS 개발만 가능하므로 macOS를 기준 구현으로 개발한다.
- 사용자가 명시적으로 전환·해제를 요청할 때까지 유지하며, 주말 종료만으로 자동 전환하지 않는다.
- 정책 전환 시점의 코드 기준: `b1db15e9e1e5d697fec39d1754344d9b7ba6fc26`. 이번 전환은 문서 변경만 포함하며 앱 구현은 변경하지 않았다.
- 정책: [AGENTS.md](../../AGENTS.md). 목표 동작: [현재 기능 명세](current-spec.md).
- 기존 Windows CI는 유지한다. CI 통과, 실제 Windows PC 수동 검증, macOS와의 기능 동등성은 별도로 판단한다.
- 이전 [macOS 차이 기록](macos-catchup.md)은 근거와 ID를 보존한다. 아래 기존 항목의 후속 결정·진행 상태는 이 문서에서 관리한다. 정책 전환은 기능 차이의 해결이나 검증 완료를 의미하지 않는다.
- 이번 정책 전환에서는 기존 기록을 확인했으며 새로운 코드 비교, 앱 빌드·테스트 실행, 실제 OS 재현, 최신 CI 결과 확인은 수행하지 않았다.

## macOS에서 확정된 변경의 반영 대기

전환 이후 새로 확정된 플랫폼 공통 변경은 아직 등록되지 않았다. 대기 항목이 없다는 사실은 기능 동등성을 뜻하지 않는다.

## 기존 차이의 후속 검토

### MAC-001: 설정 입력 검증의 차이

- 상태: 기존 코드상 차이 확인 / 공통 정책 결정 및 실행 검증 대기. 추적을 위해 기존 ID를 유지한다.
- 변경 이유·근거·관련 코드와 테스트: [기존 MAC-001 기록](macos-catchup.md#mac-001-설정-입력-검증의-차이). 동일한 버전 1 설정의 허용·거부 결과가 다를 수 있다.
- 기대 동작: macOS 개발 과정에서 공통 입력 정책을 확정하고 현재 명세에 반영한다. 기준 플랫폼이라는 이유로 macOS의 모든 기존 동작을 자동 채택하지 않는다. 손상 파일 보존 요구는 유지한다.
- Windows 수용 기준: 빈 문자열·공백뿐인 이름, 선택 필드의 생략/null/빈 문자열, Unicode 공백·제어문자를 포함한 공통 JSON 사례에 대해 확정된 정책과 일치하는 결과를 검증한다. 양쪽 저장 결과의 교차 로드와 거부된 파일의 보존을 확인한다.
- 영향과 예외: 설정 호환성 차이는 확인되어 있으나 실제 데이터 손실이나 보안 취약점은 미확정이다. Windows 즉시 수정 필요성은 미확정이며, 동결 중 수정이 필요하면 사용자에게 영향과 예외 필요성을 보고한다.

### MAC-002: SSH 로그를 통한 인증 도움·연결 판정 조건의 차이

- 상태: 기존 코드상 차이 확인 / 실제 OS 로그 재현 및 공통 정책 결정 대기. 기존 ID를 유지한다.
- 변경 이유·근거·관련 코드와 테스트: [기존 MAC-002 기록](macos-catchup.md#mac-002-ssh-로그를-통한-인증-도움연결-판정-조건의-차이). 로그 문자열별 조건이 달라 실제 사용자 영향 확인이 필요하다.
- 기대 동작: 인증 복구가 필요한 실패를 안내하고 포워딩 개설 실패를 연결 성공으로 표시하지 않는다. 각 OS의 실제 로그와 종료 처리를 검증하며 macOS의 문자열 목록을 그대로 복사하는 것으로 완료하지 않는다.
- Windows 수용 기준: 인증 실패·키 로드 실패·호스트 키 문제·로컬 및 원격 포워딩 실패·ProxyJump 로그로 기대 분류와 준비 판정을 검증한다. 실제 SSH 수명까지 포함해 잘못된 connected 상태가 없는지 확인한다.
- 영향과 예외: 실제 오판정과 보안 영향은 미확인이다. Windows 즉시 수정 필요성은 미확정이며, 동결 중 수정이 필요하면 사용자에게 영향과 예외 필요성을 보고한다.

## 미확인 영역과 OS 고유 동작

이전 기록의 [추가 확인이 필요한 영역](macos-catchup.md#추가-확인이-필요한-영역)은 계속 미확인 상태다. 연결 이벤트·절전 복귀, 설정 저장·권한·호환성, 프로세스 정리·인증 복구, UI와 OS 통합, 실제 빌드·CI·실사용 결과를 재개 시 대조한다. Windows의 포트 재사용 등 OS 고유 동작은 공통 요구사항과 구분한다.

## 항목 관리 방법

새 공통 변경은 `WIN-001`부터 고유 ID를 부여하고 아래 정보를 남긴다. 기존 항목은 ID를 유지한다. 방향이 바뀌면 같은 항목을 갱신하여 최종 요구사항을 분명히 한다.

- 상태: 검토 대기 / 반영 대기 / 구현 완료·검증 대기 / 검증 완료 / 대상 제외.
- 변경 이유와 영향, 확정된 기대 동작 및 명세 위치.
- 관련 macOS·Windows 코드와 테스트, 가능하면 변경 커밋.
- Windows 수용 기준과 실제 검증 결과. 미수행·제외된 검증은 이유와 함께 표시.
- 설정 호환성·보안·데이터 손실 영향 및 Windows 동결 예외 필요성.

macOS 전용 UI·OS 변경은 이식 목록에 넣지 않는다. 구현만 끝났거나 테스트가 제외된 항목을 검증 완료로 표시하지 않는다. Windows 재개 시 이 문서와 현재 명세, 양쪽 실제 구현·테스트를 다시 대조한다.
